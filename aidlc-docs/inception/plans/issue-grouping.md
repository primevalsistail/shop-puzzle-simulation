# OPEN issue のグルーピング — 束ごとに1サイクルで捌く

**作成**: 2026-09-11
**最終更新**: 2026-09-11（束A 完了・新規 issue 5件を反映）
**対象**: OPEN **39件**（2026-09-11 時点。`gh issue list` で取得）
**用途**: サイクルの対象を「issue 1件」ではなく「**束1つ**」で選べるようにする

## なぜ作ったか

issue 一覧は**残っているものの集合であって、順番でも単位でもない。**
1件ずつ着手すると、**同じファイルを何度も開き、同じ判断を何度もし、同じ測定を何度もやる。**
先例がある — #45 は #25・#35・#36 の3件を「**測り直す計算が共通**」という理由で1件にまとめた。
あれを issue 全体に対してやったのがこの文書。

## 束の切り方（判定基準）

次の**どれか1つでも満たすなら同じ束**にする。

1. **判断が1つで済む** — 一度決めれば束の中の全部が決まる（例: 島の需要差を需要表で出すか客構成で出すか）
2. **触る場所が同じ** — 同じファイル・同じ機構を開く（例: `TimeManager` に集まるもの）
3. **測定が同じ** — 一度測れば束の中の要否が全部決まる（例: 稼ぎ密度と時間の分布）

次のどれかなら**束を分ける**。

- **前提が違う**（片方が片方の完了を待つ）
- **判断者が違う**（技術判断とPO判断が混ざる場合は、PO判断の側を束の入口に置く）

## 束を締めるときの規則（CLAUDE.md より）

- 束の中で「今回は扱わない」と判断したものは、**その場で issue にして番号をこの文書へ書き戻す**
- 実装が **`main` に入った時点で close する。**ブランチにあるだけでは閉じない
- close のコメントに**コミットハッシュと実装内容**を書く。issue 本文と実装が違うなら**何をどう変えたか**も
- **残作業があるなら、先に別 issue へ切り出してから閉じる**
