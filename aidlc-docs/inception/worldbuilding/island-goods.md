## 1. 土台 — **四島は「四季が場所に固定されたもの」**

| 島 | 気候（[world.md](world.md) §1） | ＝ |
|---|---|---|
| ハルヴェラ島 | 温暖 | **春** |
| リナツィア島 | 陽が強く、暑い | **夏** |
| ノアキータ島 | 実りが絶えない | **秋** |
| ミフユリア島 | 雪が絶えない | **冬** |
| （海） | 四島を結ぶ穏やかな海 | **通年**（どの季節にも属さない） |

季節が時間の中で巡るのではなく、**空間に並んで固定されている**世界。

### ⚠ 季節の名前はゲームに出さない

[world.md](world.md) §1:「**この世界に四季という観念はなく、作中でも画面でも季節名は出さない。**」

**春夏秋冬は設計側の土台であって、ゲームの中の言葉ではない。**
品名に季節の語を入れない。world.md の気候の表記（温暖／陽が強く暑い／実りが絶えない／雪が絶えない）は
四季の言い換えなので、**world.md §1 の書き換えは不要。**

## 2. 産地の決め方 — **旬のイメージ、それだけ**

> **その品が一般的にどの季節のイメージか。それで産地が決まる。**
> **旬が無い（通年で採れる）ものは、海 ＝ 産地 `なし`。**

### 生育条件は持ち込まない（★これが肝）

**「その土地でどうやって育つのか」は問わない。**

- 冬を越すことが引き金で春に芽吹く ／ 実るには春夏の生育期間が要る ／
  一年じゅう雪の下では畑作が成り立たない —— **どれも考慮しない**
- レモンは冬のイメージなので**ミフユリア（冬）**。雪の島にレモンの木があってよい
- **理由**: ゲームは生育を模擬しない。説明を足すと世界観に前提が増える
  （[world.md](world.md) §2「前提を崩す要素を足さない」）。
  そして**プレイヤーに伝わるのは生育条件ではなく季節のイメージのほう**

### この規則が持つ性質

- **読み手の裁量が入らない。**「この品の旬はいつか」は調べれば決まる
- **品ごとに1回で決まる。**島を見比べる必要がない
- **重複が構造的に起きにくい。**実際、この規則で 6件 → 1件（ぶどうのみ）に減った

## 2-A. 却下した規則 ★重要 — 復活させようとしたとき読む

当初この文書は**逆向き**に書かれていた。**「品に産地を割り当てる規律」**を作ろうとして失敗している。
同じ形を再発明しないために、失敗の実物を残す。

**却下した規律**: 「その品を、気候が言い分けている性質まで具体化してから突き合わせる。
当てはまる島が2つ以上なら、品の記述が粗いので具体化し直す」

**実際に使うとこうなる。**`繊維になる草` の産地を決める:

| 気候の語 | 当てはまるか |
|---|---|
| 穏やかな環境で育つ（ハルヴェラ） | 育つ |
| 陽で乾く（リナツィア） | 乾く |
| 量が採れる（ノアキータ） | 採れる |
| 寒さに耐える（ミフユリア） | 耐える |

**4島とも当てはまる。**規律に従って具体化すると `寒さに耐える丈夫な繊維の草` → ミフユリア。
**しかし `穏やかな環境で育つ柔らかい繊維の草` → ハルヴェラ とも書ける。どちらも規律を守っている。**

**この規律がやったのは、恣意性を「どの島を選ぶか」から「品にどの修飾語を付けるか」へ移しただけ。**
**手続きの形をしているぶん、恣意性が見えなくなる点で前より悪い。**

### さらに、この規律は一次情報を取り違えていた

根拠に [characters.md](characters.md) の商人の「扱い品の方向」を使っていたが、
**characters.md 自身が「縛り：扱い品は島の気候から導く」と注記している。**あれは**導出結果**であって
産物の定義ではない。**一次情報は world.md §1 の気候。**
導出結果を前提にすると、「草木」という語を草と木に読み分けるような作業が発生する。
また**商人の設定が変わると産物の話まで揺れる。逆であるべき。**

## 3. 産地 `なし` ＝ **海**

[world.md](world.md) §1: 「気候の違う**四つの島**と、**それを結ぶ穏やかな海**でできた世界」。

四島がそれぞれ一つの季節に固定されている以上、**旬のある品は必ずどれかの島に属する。**
**旬を持たない（通年で採れる）ものだけが、どの島にも属さない。**

- **どの島でも手に入る**（→ [Phase 2 / U4](../application-design/cycle4-phase2-axes.md)「産地を持たない品は、どの島でも並ぶ」）
- **詰み回避**を担う（島を1つ外しても買えるものが必ずある）
- **島の個性のコントラスト**を担う

**品を `なし` に寄せない。**割り当てに困った品の逃げ道にすると、島を巡る理由が消える。

## 4. 名前についての縛り

[world.md](world.md) §7: **「島名・人名・船名のほかに、固有名詞を持たない世界」。**

- 品の名前は**普通名詞**にする。「ハルヴェラ織」のような固有名詞由来の品名を作らない
- **季節名を含めない**（「春〜」「新〜」など）。§1 の⚠のとおり
- 設定用語は「**取り合わせ**」ひとつだけ。品の名前で新しい用語を増やさない
- **カテゴリ語を品名にしない。**「香草」「果実」「魚」は商品を指していない。具体的な品名にする

## 5. 産地と「向く土地」は別（[Phase 2 §4-E](../application-design/cycle4-phase2-axes.md)）

**この文書は `産地` だけを扱う。`向く土地` は決めない。**

- 産地 = **どこで採れるか** ／ 向く土地 = **どこで役に立つか**
- **一致する場合が多いが、一致しない品があってよい**
- 一致しない品こそが、[char.md](char.md) の
  「**どの土地へ持っていくと一番『持ってきた甲斐』が出るか**」という判断を作る

## 6. 「素材」と「加工品」の線について（★誤解の記録）

サブセッションへの依頼で「**素材＝そのまま採れるもの。加工品は不可**」という条件を課したが、
**これはアイテム体系の要件ではなかった。**

体系が定めているのは [Phase 2 §4-B](../application-design/cycle4-phase2-axes.md) の
**「レシピを持たない品は tier1」**だけで、**その品がどう作られるかは問うていない。**

- この誤解のせいで**塩が素材から外され、代わりに「海水」を置く案**が出た。
  海水は仕入れの画も売る画も成立せず、船が海に浮いているのに船倉へ積むのも滑稽だった
- **塩にレシピを与えなければ、塩は tier1。**海の品として置けばよい

**教訓**: サブセッションに課す条件が、体系の要件なのか自分が足した縛りなのかを区別する。
