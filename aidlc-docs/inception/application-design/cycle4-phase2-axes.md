## 0. 結論

### **軸は 5 本。**（N = 2）

| # | 軸 | 問い | 値 |
|---|---|---|---|
| 1 | **主種類** | これは何であるか | `食料` `飲みもの` `衣類` `道具` |
| 2 | **tier** | どれだけ加工されているか | 1〜（**導出**） |
| 3 | **産地** | どの島で仕入れられるか | 四島 ＋ `なし` |
| 4 | 面① **贅沢さ** | 客がどれだけ奮発して買うか | `日用` < `上等` < `贅沢`（順序あり） |
| 5 | 面② **向く土地** | どんな土地で役に立つ品か | `寒い土地` `暑い土地` `温暖な土地` `実りの土地` `どこでも` |

規則が参照しない属性: **かたち・大きさ** ／ **表示** ／ **価格**（導出）

## 1. 進め方 — 規則を先に列挙した

PR-3「**列挙するなら、アイテムより先に規則を列挙する**」に従い、
語彙を先に発明せず、**書きたい規則を先に並べて、そこから必要な語彙を逆算した。**

この順で進めた結果、**Phase 1 が候補に挙げていた面が3本とも落ちた**（保存・客層・消耗 → §3）。
アイテムを先に挙げていたら、3本とも「それらしいから」という理由で残っていた。

| R3 | 暮らしの品どうしを並べるとまとめて売れる | 贅沢さ |

| R6 | 加工の深い品の隣にその系統の浅い品を置くと売れやすい（手仕事が見える） | tier ／ 主種類 |

## 3. 落とした面（★重要 — 復活させようとしたとき読む）

### 3-A. 「保存」（生鮮／常温）を落とす

**Phase 1 で問いごと取り下げた「傷むか（鮮度・時間劣化）」を、名前を変えて入れ直すことになる。**
時間劣化の機構が無い以上、`生鮮` の**定義文が書けない**（「生鮮とは傷みやすいものである」→ 傷む機構が無い）。

「生鮮どうしは売れにくい」という取り合わせ規則は書けるが、**それは効き目であって値の定義ではない**。
定義できない値を置くのは PR-1（説明が要る名前は負け）に触れる。

- **ユーザー判断**: 「鮮度は面倒」
- **復活させる条件**: 鮮度・時間劣化の機構を入れると決めたとき。**Phase 1 に戻って問いを立て直す**

### 3-B. 「客層」（子供向け／職人向け）を落とす — **向きが逆だった**

**「誰に売れやすいか」は品の事実ではなく意味づけである**（§2#9）。品側ではなく**規則側**に置く。

| | 客の種類を1つ増やす | 品を1つ増やす |
|---|---|---|
| 品側に `客層` を置く | **既存の全品を見直して付け直す** | 客層を1つ書く |
| **規則側に条件式を置く** | **条件式を1本書くだけ**。既存品は0行 | **0行**（既存の全客の好みが自動で決まる） |

- 形式上は INV-5 違反ではない（INV-5 は「**品**を足すとき」の条件）。
  ただし §6 で隣接シナジーの ID 直書きを落としたのと**同じ壊れ方**であり、INV-5 はこれを防ぐための条件
- `子供向け` は「子供という客が世界に居る」ことに依存する値。**登場人物が変わると品の属性が変わる**。
  `贅沢さ` `tier` `産地` にはこの依存がない
- **島は例外**（→ §5-E）。world.md §1 で四島に確定していて**増減しない**ため、この壊れ方が起きない
- **復活させる条件**: 主種類4 × 贅沢さ3 = 12通りでは「誰が買うか」が書き分けられないと判明したとき。
  そのとき足すのは**客の名前を値にした面ではなく、品自体の事実である面**

### 3-C. 「消耗」（使い切る／残る）を落とす — **根拠の事象が存在しなかった**

消耗を置いた根拠は「**同じ客が繰り返し買う**」だった。しかし**この世界の客には同一性が無い**
（[characters.md](../worldbuilding/characters.md)「個人を作らない」）。**「同じ客」という判定をそもそもしない。**

草案が挙げた「同じ品をまとめて買う客」も、同一人物の再来店ではなく**1回の取引での複数個購入**である。

- **ユーザー判断**: 「客について『同じ客』という判定をそもそもしない」
- **申し送り（Phase 4）**: 回転率を担うのが `贅沢さ` 3値だけになったため、
  **「最適戦略が一致していないか」の検査の重要度が上がる**。品ごとの戦略差は
  残る4つ（利益・時間・**場所**・現在地）で作る

### 3-D. 客のモデルは Cycle 4 で定義しない

**調査結果**: 来訪モデル（何人来るか／島で変わるか／何を見て選ぶか）は**どこにも定義がない**。
characters.md 末尾に4類型と縛り2件があるだけで、world.md §8 の未決にも挙がっていない。
コード（[CustomerSimulator.ts](../../../src/components/simulation/CustomerSimulator.ts)）には
**客という実体も類型も存在せず**、毎分30%で来店判定して全スロットを独立に購買判定するだけ。

- **ユーザー判断**: Cycle 4 はアイテム体系に閉じたまま終える。**客は Cycle 5「客と需要」で定義する**
- Cycle 4 が用意するのは**条件言語**まで。客の好み規則は同じ条件言語で Cycle 5 に書ける

## 4. 各軸の定義

### 4-A. 主種類 — 「これは何であるか」

> **主種類とは、その品を人がどう扱うものかである。**

| 値 | 定義（「〜ものである」） | 現行13品からの例 |
|---|---|---|
| `食料` | 口に入れて腹を満たすもの | 小麦粉、トマト、りんご、パン、トマトソース、サンドイッチ |
| `飲みもの` | 口に入れて喉を潤すもの | ミルク、ワイン |
| `衣類` | 身につけるもの | 布 |
| `道具` | 手に持って使うもの | ボトル、木材、本 |

- **必ず1つ・不変。**棚の整理・表示・数え上げに使う。設計の中心ではない（§2#6）
- **切り方を全値で揃える（動詞）。**§3「書物」の失敗＝他は動詞で切っているのに1つだけ素材で切った、を避ける
- **`原料` という値は置かない。**「用途を持たないもの」は**用途の不在**で切っており、
  他の値（用途）と切り方が違う＝**§3「書物」と同型**。木材・布は用途側へ寄せる
- **⚠ INV-1 のための言い方**: 「**最終的に何になるか**」で決めない。レシピを足すと値が動く。
  **その品そのものを人がどう扱うか**で決める（小麦粉は口に入るものなので `食料`。パンになるからではない）
- **`道具` は将来分割してよい。**そのとき `道具` だった品の値は書き換わるが、これは「追加」ではなく
  「**変更**」であり、INV-1 が明示的に区別している側（§INV-1「例外ではなく区別」）。
  **Phase 3 で `道具` に何品入るかを見てから判断する**

### 4-B. tier — 「どれだけ加工されているか」

> **tier とは加工の深さである。**`tier = 1 + max(材料の tier)`、レシピを持たない品は 1。

- **手で書かない。`ALL_RECIPES` から導出する**（INV-3。型にフィールドを置かない）
- 絶対値なので、レシピを足しても既存品の tier は動かない（INV-1）
- 天井は10、運用は5〜6（§4-E）。**数値は Phase 3**

### 4-C. 産地 — 「どの島で仕入れられるか」

> **産地とは、その品が採れる島である。**

- **必ず1つ・不変。**値は `ハルヴェラ` / `リナツィア` / `ノアキータ` / `ミフユリア` / `なし`
- **`なし` は明示的な値。**空欄は型エラー（Phase 1 / D2）
- `なし` の品は、島の個性のコントラストと詰み回避を担う
- **どの品がどの島かという値は Phase 3。**`なし` の割合の上限も Phase 3

### 4-D. 面① 贅沢さ — 「客がどれだけ奮発して買うか」

> **贅沢さとは、その品を買うときに客がどれだけ奮発するかである。**

| 値 | 定義 |
|---|---|
| `日用` | 無ければ困るので、値段を見て買うもの |
| `上等` | 無くても困らないが、暮らしを良くするもの |
| `贅沢` | 要るから買うのではなく、欲しいから買うもの |

- **必ず1つ。**`なし` を持たない（どの品にも買う理由がある）
- **順序を持つ**（`日用` < `上等` < `贅沢`）。条件式に `贅沢さ >= 上等` と書ける
- **価格（Q6）とは別の問い。**価格は「**いくらか**」に答え、贅沢さは「**なぜ買うか**」に答える（INV-2a）。
  **安い贅沢品も、高い日用品も存在してよい。**これが両者が別軸である証拠
- **§3「tier ＝ 価格帯」を繰り返さないための線**: 贅沢さは価格の**入力**（P1 の倍率）であって、価格の言い換えではない
- **回転率を担う唯一の軸**（消耗を落としたため）。P3 の警告への受け皿

### 4-E. 面② 向く土地 — 「どんな土地で役に立つ品か」

> **向く土地とは、その品が役に立つ土地の性質である。**

| 値 | 定義（**2026-09-07 確定**） |
|---|---|
| `寒い土地` | **体を温める**のに役立つもの（**熱を守る** ／ **熱を与える**） |
| `暑い土地` | **体を冷やす**のに役立つもの（**熱を逃がす** ／ **冷たさを与える**） |
| `温暖な土地` | **外で過ごす時間の長い暮らし**に役立つもの（軽装・持ち歩き・生鮮） |
| `実りの土地` | **多すぎる収穫を捌く**のに役立つもの（束ねる・容れる・蓄える） |
| `どこでも` | 土地を選ばないもの（既定）。**用途が一つに定まらないもの**もここ |

### ★2026-09-07 の確定 — Phase 3 の評価が出した「揺れ5件」を閉じた

判定役の条件「ストレステスト前に揺れを閉じること」への対応。
**開いたまま新品を振らせると、分布が「軸の性能」ではなく「振った人の読み」を測るため。**
→ 経緯は [suited-land-wording-questions.md](../../construction/item-taxonomy/evaluation/suited-land-wording-questions.md)

| # | 揺れ | 決着 | 根拠 |
|---|---|---|---|
| 1 | 保存食6品を `実りの土地` に含めるか | **含めない**（「蓄える」は**手段**に限る） | 実りの土地の人は食べものが余っている。保存食を持ち込むのは**需要の向きが逆**。母数の薄さは定義を曲げず**品を足して**埋める |
| 2 | 温かい飲食8品を `寒い土地` に残すか | **残す。定義を「体を温める」に広げ、`暑い土地` も対称に「体を冷やす」へ** | **暑い側はすでに広い読みで振られていた**（氷菓子は「熱を逃がす」ではなく「冷たさを与える」）。寒い側だけ狭く読むのが不整合だった。⚠ 外すと残る8品が**全部 `衣類`** になり、この軸が `主種類` の言い換えになる |
| 3 | 生魚5品（まぐろ・いわし・いか・鮭・かに） | **`温暖な土地` に変更**（例示「生鮮」どおり） | `どこでも` にしていた理由「四島すべての海で獲れる」は**産地の話**で、`向く土地` に持ち込むと **INV-2a（一軸一問）に触る**。定義文は触らず、判定理由だけを取り除いた |
| 4 | 持ち歩きの線引き（おにぎり vs 干し肉） | **「持ち歩くために作られた形をしているか」を定義文に明記** | 品を手に取れば決まる基準なので INV-2b を保てる。品の振り直しが発生しない |
| 5 | 用途が広すぎる素材5品（竹・革・帆布・オリーブ・蜜蝋） | **「用途が一つに定まらないものは `どこでも`」を明記** | `どこでも` に「選ばない」と「**選べない**」の2種があることを、取りこぼしではなく**定義として認める**。#23「気候は何が育つかしか決めない」と揃う |

**⚠ `src/taxonomy/axes.ts` に改訂前（INV-2b 違反として捨てたはず）の文言が残っていた。**
Phase 3 の評価が「定義文の版が食い違っている可能性」として指摘し、実在を確認。**この確定に合わせて揃えた。**

### ★2026-09-06 の改訂 — INV-2b 違反を直した（Phase 3 の発見）

**改訂前の定義は、2つの違う問いに答えていた。**

| 改訂前 | 何を問うていたか |
|---|---|
| `寒い土地` / `暑い土地` = 「寒さ／暑さを**しのぐ**のに役立つもの」 | **品の性質。**品を手に取れば決まる |
| `温暖な土地` / `実りの土地` = 「その土地の**暮らしで使われる**もの」 | **買い手の暮らしぶり。**品を見ても決まらない |

**発見の経緯**: Phase 3 で110品に `向く土地` を振らせたセッションが、
**こちらの疑いを一切伝えていない状態で**独立に指摘した。

- **`実りの土地` の定義文が二通りに読めた** — 「実りの暮らしの中心にあるもの」なら米・栗・ぶどうで**20品超**、
  「実りの土地で役に立つもの」なら縄・かご・塩で**5品**。**同じ定義文から4倍違う結果**
- **`温暖な土地` は構造的に `どこでも` と重なる** — 穏やかな気候とは「しのぐべきものがない」ことなので、
  「穏やかさゆえに要るもの」が存在しにくい。振れた11品はほぼ全部「**春の**季節感を持つ品」で、
  気候ではなく**季節**にすり替わっていた
- **`どこでも` が 62／110 品**になった。「しのぐ」でも「暮らしぶり」でも語れない品が全部そこに落ちる構造

**改訂後は4値とも「その土地で何が起きるか／人が何に困るか」で揃っており、品を見れば決まる。**
値の数は5のままで、**軸も値も増やしていない。**

> **⚠ 雨と夜（暗さ）は値にしない。**「雨をしのぐ」「暗さをしのぐ」は5値のどこにも無いが、
> **雨も夜も四島すべてにある**ので土地の性質ではない。ろうそく・傘・合羽が `どこでも` になるのは
> 取りこぼしではなく正しい判定。

- **必ず1つ。**`どこでも` は明示的な値
- **品は島の名前を知らない。**知っているのは「自分は寒い土地で役に立つ品である」ことだけ。
  島との結びつけは**4行の需要表**（D1）が持つ。**島の気候設定を変えても品は無傷**
- **産地（4-C）とは別の問い。**産地は「**どこで採れるか**」、向く土地は「**どこで役に立つか**」（INV-2a）。
  ミフユリア産の毛織物が寒い土地に向く、のように**一致する場合が多いが、一致しない品があってよい**
  （ノアキータ産の干し肉が寒い土地に向く、など）
- **島を品側に置いてよい理由**: world.md §1 で**四島に確定していて増減しない**。
  客層（§3-B）で問題になった「外部が増えると既存の全品を書き換える」が起きない

### 4-F. 規則が参照しない属性

| 属性 | 定義 | 備考 |
|---|---|---|
| かたち・大きさ | **船倉で占める升目の形である** | 「場所」という制約を作る。**消耗を落とした分、戦略差を担う比重が上がる**。数値は Phase 3 |
| 表示 | **画面での見え方である**（名前・色・絵） | 規則から参照しない |
| 価格 | **その品がいくらで売り買いされるかである** | **導出**（INV-3）。tier1 のみ手書き（P1）、tier2以上は積み上げ（P2） |

## 5. 条件言語

**述語は2種類。**アイテムの軸を見るものと、ゲームの状態を見るもの（Phase 1 §5）。

```
述語 ::= アイテム述語 | 状態述語

アイテム述語 ::= <軸> <演算子> <値>
    主種類   == '食料'
    tier     >= 4
    産地     == 'なし'
    贅沢さ   >= '上等'          // 順序を持つのは tier と贅沢さ
    向く土地 == '寒い土地'

状態述語 ::= <計量>(<対象>) <演算子> <値>
    累計販売数(この品) >= N       // U2 の解禁条件
    現在地            == 'ミフユリア'  // D1 の島の需要 / U3 の島の品揃え

条件 ::= 述語 | 条件 かつ 条件 | 条件 または 条件 | でない 条件
```

- **どちらの述語も ItemId を書かない** → **INV-4 は維持される**
- **`この品` は指示子であって ID ではない。**規則は自分が今どの品に当たっているかだけを知る
- 演算子は `==` `!=` `>=` `<=` `>` `<`。**順序を使えるのは tier と贅沢さだけ**
- **産地距離は入れない。**Phase 1 §5 の有力案「産地から遠い島ほど高く売れる」は**不採用**
  （ユーザー判断「どの島で売れるかはあってもいいけど、それは距離に依存しない」）。
  「よその島のもの」は `産地 != 現在地` で書ける（D2）

### 効き目 — 種類 × 適用範囲

| | |
|---|---|
| **種類** | `売れやすさ`（客に選ばれる率）／ `値段`（売値）／ `集客`（桟橋に来る客の数） |
| **範囲** | `その品` ／ `店全体` |

- 「この2品を隣に置くと**その2品が**売れやすい」と「**店全体の**客足が伸びる」を同じ書式で書ける
- **現行コードは3種とも品ごとに効く実装。`店全体` は新しい機構**（Phase 3 で実装する）
- **倍率は Phase 3**

### 規則の形（すべて同じ条件言語を使う。§2#8）

```
取り合わせ 層1 : { 甲: 条件, 乙: 条件, 効き目, 範囲, 倍率 }      // ID を書かない
取り合わせ 層2 : { 甲: ItemId, 乙: ItemId, 効き目, 範囲, 倍率 }  // 名物コンビ。全部消しても成立する（INV-4）
島の需要      : { 条件, 効き目, 範囲, 倍率 }                     // 下記の4行
入荷解禁      : { 条件, 並ぶ先 }                                // 並ぶ先 = 島の商人 / 行商人バレン
客の好み      : { 客の類型, 条件, 補正 }                         // Cycle 5 で書く。器だけ用意する
```

### 島の需要表（D1 — 調整はここ4行に集まる）

```
向く土地=='寒い土地'   かつ 現在地=='ミフユリア'  → 売れやすさ ↑（その品）
向く土地=='暑い土地'   かつ 現在地=='リナツィア'  → 売れやすさ ↑（その品）
向く土地=='温暖な土地' かつ 現在地=='ハルヴェラ'  → 売れやすさ ↑（その品）
向く土地=='実りの土地' かつ 現在地=='ノアキータ'  → 売れやすさ ↑（その品）
```

**品を1つ足すときに書くのは `向く土地` の1語だけ。**バランス調整はこの4行だけを触る。

## 6. 検算 — Phase 0 の条件を満たすか

| 条件 | 判定 |
|---|---|
| INV-1 追加しても既存は変わらない | 主種類は「その品そのものの扱い」で決める（§4-A の⚠）。tier は絶対値。産地・贅沢さ・向く土地は品固有 → **満たす** |
| INV-2a 一軸一問 | 主種類=何であるか／tier=加工の深さ／産地=**どこで採れるか**／贅沢さ=なぜ買うか／向く土地=**どこで役に立つか**。**重なりなし** → 満たす |
| INV-2b 値がすべて同じ問いへの答え | 各軸の定義表が「値 X は〜ものである」で同じ形に揃っている。`原料` を置かなかったのはこの検査による → **満たす** |
| INV-3 導出できる属性は持たない | tier・価格（tier2以上）・レシピ由来は型に置かない → 満たす |
| INV-4 規則はアイテムを知らない | 層1・島の需要・入荷解禁のいずれにも ItemId が出ない。層2のみ ID を書き、消しても成立 → 満たす |
| INV-5 追加コストが定数 | 品を足す ＝ 5軸の値を書いた定義1件。既存行は0行変更。島の需要表も触らない → **満たす** |
| INV-6 作った品は材料より高い | P2（積み上げ式）で構造的に満たす。P1 の品ごと補正で破りうるので Phase 4 で検査 |
| PR-1 説明が要る名前は負け | 主種類の値・`日用/上等/贅沢`・`寒い土地/暑い土地/どこでも` はすべて字面で通る。`原料` `生鮮` を落としたのはこの規律 |
| PR-2 UI制約は分類設計への制約ではない | 値の数の決定理由に表示・幅が出ていない（4値・3値・5値はいずれも規則からの逆算） |
| PR-3 アイテムより先に規則を列挙する | §2 で規則を先に列挙し、§0 で逆算した。面が3本落ちたのはこの順序の効果 |

**すべて満たす。**

## 7. Phase 3 への申し送り

### 実装するもの
- 型定義（5軸）＋ 実アイテム20品 ＋ 規則評価器
- **効き目の適用範囲 `店全体`** — 現行コードに無い新しい機構
- **島の需要表 4行**（D1）
- 状態述語 `累計販売数(この品)` `現在地`

### 確かめること
- **`道具` に何品入るか**。多すぎるなら分割する（§4-A）
- **`向く土地` が `どこでも` に偏らないか**。偏るなら D1 が効かない
- **産地 `なし` の割合の上限**（多すぎると島を巡る理由が消える）
- **`主種類4 × 贅沢さ3` の12通りに品が散るか**。片方に寄るなら軸が余っている
- U2 の解禁条件の数（Phase 1 §5 は100個と仮置き）

### Phase 4（ストレステスト）で重くなった検査
**消耗を落とした（§3-C）ため、回転率を担うのが `贅沢さ` 3値だけになった。**
Phase 1 §5 の警告「`利益/時間` が一律だと何を買ってどう売っても結局同じ」に対する弾が1つ減っている。

- 新品30個について**最適戦略が一致していないか**の検査を必ず行う
- 戦略差は残る4つ（利益・時間・**場所**・現在地）で作る。
  とくに**かたち・大きさ**（§4-F）の比重が上がった

### Cycle 5「客と需要」へ
- 客の来訪モデル（何人来るか／島で変わるか／何を見て選ぶか）は**未定義**（§3-D）
- 客の好み規則 `{ 客の類型, 条件, 補正 }` の器は用意済み。**同じ条件言語で書ける**
- そのとき「誰が買うか」は**規則側**に置く（§3-B）。品側に客層を足さない
