### ★2026-09-07 — 素材の産地依存は残す（遊ぶ人5人に意見を募った）

**発端**: ユーザーの疑問「ずっと産地に依存するのも微妙。100個売ったらどの島でも買えるようにした方がいいか」

**説明書1ファイルだけを渡した独立5セッション**（効率型・のんびり型・パズル型・世界観型・素）に意見を募った。
コード／設計文書／git 履歴／こちらの推奨／過去の却下理由は**一切渡していない**。
→ [5人の意見](construction/item-taxonomy/evaluation/material-unlock-player-opinions.md)
／ [説明書](construction/item-taxonomy/evaluation/material-unlock-player-brief.md)

- **提案された形に賛成 0/5。**5人とも**「産地縛りそのものは残してほしい。むしろ一番いいところ」**
- **升目のやりくりが消えること**を5人全員が最重要として挙げた（こちらの想定より重い）
- **不満の在りかが違った。**5人が同じ3つを挙げた:
  **(a) 知りようがない**（1周目に30日前の島の素材が要ると初めて知る）／
  **(b) 「あと1個」で40日、打つ手がない**／ **(c) 買い物リストが固定され帳簿仕事になる**
- **代案は2つに収束**: **割高・少量の調達（5/5・機構が増える）** ／ **不足を先に見せる（4/5・軸も規則も増えない）**

**⚠ こちらも判定役も見ていなかった穴**（4人が独立に指摘）:
**「100個売る」条件そのものが投げ売り作業を最適化する。**素材を安値でダンプするのが解放の最短ルートで、
**加工が面白いゲームなのに加工しないのが最適な区間ができる。**
さらに**よく使う素材ほど生では売らないので解放されない**（羊毛は毎回フェルトにする）。
判定役は検査5でこの条件を落としたが、**理由は「対価が143倍散る」でこの穴ではなかった。**

**決定**（→ [質問票](construction/item-taxonomy/evaluation/material-unlock-questions.md)）
- **素材の解禁は入れない。**産地依存を最後まで残す（**産地軸が働く唯一の層＝tier1 の50品**を守る）
- **(a)(c) には手を打つ** → **issue #33**「不足を先に見せる」（**Cycle 4 の外**・軸も規則も増えない）
- **(b) は保留** → **issue #34**。割高・少量の調達は 5/5 の本命だが**機構が1つ増える**ため採らない。
  **#33 を入れてから、残る不満だけを見て判断する**

### ⚠ Phase 3 で `向く土地` の INV-2b 違反が見つかり、Phase 2 に戻って直した

**110品に `向く土地` を振らせたセッションが、こちらの疑いを一切伝えていない状態で独立に指摘した。**

> `寒い土地`／`暑い土地` は**品の性質**を問うている（品を手に取れば決まる）。
> `温暖な土地`／`実りの土地` は**買い手の暮らしぶり**を問うている（品を見ても決まらない）。
> `実りの土地` の定義文は二通りに読め、**同じ定義文から4倍違う結果**（20品超 vs 5品）。
> `どこでも` 62／110 は**軸の設計を測っている数字**。

**修正**（→ [Phase 2 §4-E](inception/application-design/cycle4-phase2-axes.md)）:
4値すべてを「その土地で何が起きるか／人が何に困るか」で揃えた。
寒い＝**熱を守る** ／ 暑い＝**熱を逃がす** ／ 温暖＝**外で過ごす時間の長い暮らしに役立つ** ／
実り＝**多すぎる収穫を捌くのに役立つ**。**値の数は5のまま。軸も値も増やしていない。**
振り直した結果 `どこでも` 62 → 56、`温暖な土地` 11 → 19、`実りの土地` は**ぶれずに**5。

### Phase 3 で決まった主要事項（2026-09-06。詳細は [item-system.md §2 #21〜#25](inception/design-log/item-system.md)）

- **産地は「品に割り当てる」のではなく「島から品を起こす」**（#21）。
  割り当て向きだと「この品はどの島か」の選択が毎回発生する。規律を作っても
  **恣意性が〈島の選択〉から〈品への修飾語〉へ移るだけ**だった（実物を island-goods.md §2-A に保存）。
  向きを変えると**産地は選択ではなく出自**になる
- **産地 `なし` ＝ 海のもの**（#22）。world.md §1「四島とそれを結ぶ穏やかな海」から導出
- **気候は「何が育つか」しか決めない**（#23）。よって**かたちになったものはどの島も産さず**、
  着るもの・使うものは tier2 以上に来る
- **効き目の合成は加算** `1 + Σ(mᵢ − 1)`、**上限なし**（#24）。
  乗算は暴走し、上限値はバランス調整の数値（スコープ外）になるため
- **⚠ 条件言語に「軸どうしの比較」が無い**（#25）。`産地 == 現在地` が書けない。
  **U3・D2・R5 の3規則がこれを要求**しており、いまは評価器が個別に持っている。
  条件言語に足すかは Phase 4 以降の判断
- **一次情報と導出結果を取り違えない**（Step 1 で2回滑った）。
  characters.md の商人の扱い品は**気候から導かれた結果**であって産物の定義ではない。
  歯止めを island-goods.md §1-B に残した

### 2026-09-06（Phase 0・Phase 1）に決まった主要事項（詳細は [Phase 1 §5](inception/requirements/cycle4-phase1-axes.md)）

- **要素は面（facet）に分ける。**平らなタグ袋は保存性と客層を混ぜており INV-2b 違反（「書物」と同型）
- **産地を面として持ち、値に「なし」を含む。**産地なしの品が島の個性のコントラストと詰み回避を担う
- **placeable は廃止。全品売れる。**全品が「今売るか、材料にするか」の選択になる
- **売値は積み上げ式。**tier1 のみ手書き、tier2以上は `Σ材料の売値 × 加工倍率`
- **中間品は「その品を100個売る」と買えるようになる**（ただし買う方が高い＝時間を金で買う）
- **採らなかった案**: 他島でも割高（1.0〜1.3倍）で買えるようにする
  → characters.md:92 のバレンの制約（10種10個を超えると島を巡る必要がなくなる）と矛盾する
- ~~**有力案（Phase 3 で検証）**: 産地から遠い島で売るほど高く売れる~~
  → **Phase 2 で不採用**（「どの島で売れるかは距離に依存しない」）。代わりに `向く土地` と4行の需要表
- **⚠ 必ず守ること**: 加工倍率を所要時間**だけ**から決めない。`利益/時間` が一定になり
  「何を買ってどう売っても結局同じ」になる。面（贅沢／日用）による回転率の差を必ず併せて入れる

```
買値     = 材料費 + 加工利益 × 1.25
```

|---|---|---|

| フロンティア | 2品 | **12品**（日用・上等・贅沢の3層すべて） |
| #36 買値のずれ | 144倍 | **8.9倍** |

### 1. 4人が揃って言ったこと

#### 1-1. **島ごとの需要差が、画面に1文字も出ていない**（判断に要る）

**前回この4人が「ここだけは揃って面白い」と言ったもの**が、**言葉として1つも無い。**

> 「『こっちの島では〜を売る』が方針なら、**棚のどこかに『この島では』が要る。**
>  いまは棚を見ても、ここがどの島かで**置き方を変える理由が読めない**」（配置パズル好き）

⚠ **これは「足す側」なので束Mの作業順4だが、4人とも「最優先で足すのはこれ」と言った。**

#### 1-2. **ボタンの名前と、行った先の見出しが違う**（判断に要る／減らす側でもある）

| 押すボタン | 着く場所の見出し | 揃っているか |
|---|---|---|
| `🔨  工房` | `工房` | ✅ 今回揃えた |
| `⬆  改装` | `改装` | ✅ |
| `🛒  仕入れ` | **`商人のところ`** | ❌ **揃っていない** |

**`クラフト → 工房` を「同じ場所を2つの名で呼んでいる」という理由で直したのに、
仕入れだけ同じ問題が残っている。**しかもチュートリアル第4章の見出しも `仕入れ`、本文も
`「仕入れ」ボタンから素材を購入できます`。**3つ目の呼び方は無いが、2つある。**

> 「工房を直した人が、なぜ隣のボタンを見なかったのか。**同じ画面に並んでいる**のに」（やりこみ層）

#### 1-3. **同じ「手持ちの数」が、画面ごとに4通りで書かれている**（減らす側）

| 画面 | 書き方 |
|---|---|
| 持ち物一覧 | `5個` |
| 売り場（棚の区画） | `×5` |
| 工房（完成品・材料の括弧） | `パン×2(5)` ／ `小麦×3(10)` |

#### 1-5. **文言だけで投げ出す瞬間**

### 3. 意見が割れた点

### 4. 今回の削減への反論

⚠ **各項目に、[bundle-m-text-decisions.md](construction/plans/bundle-m-text-decisions.md) の
「消した理由」への当て方を書かせている。**

#### 4-1. 改装の `払えば目標が遠のく。いま買うか、我慢するか`（**最も強い反論**）

| | |
|---|---|
| **消した理由** | 「判断そのものを言い換えているだけ。**金額・段数・目標バーで足りる**」 |
| **反論**（経営シム好き・カジュアル層） | ⚠ **目標バーは所持金と連動していない。**バーは `累計売上 ÷ 100万`（`HUD.ts:93`）で、**改装で払っても1ミリも動かない。**つまり「**払えば目標が遠のく**」は**そもそも実装上そうなっていない。** |
| **理由への当て方** | **消したこと自体は正しいが、理由が違う。**正しい理由は「**バーで足りるから**」ではなく「**嘘だったから**」。⚠ **理由を間違えたまま消すと、#73 を直したときに同じ文が「今度は本当になった」として戻ってくる。** |
| **残る穴** | **判断の片方（目標側）が画面から消えた。**「いま買うか、**目標まで我慢するか**」の後半に対応する文字が**改装の画面に1つも無い**（§2-5） |

#### 4-2. 持ち物一覧の `（上限）`

| | |
|---|---|
| **消した理由** | 「`999個` と出ていれば同じこと。上限で買えないのは買う画面で分かる（`上限999` が出る）」 |
| **反論**（やりこみ層） | ⚠ **`999個` を上限だと読めるのは、上限が999だと知っている人だけ。**初見には**ただの大きい数**で、`998個` との区別が付かない。**そして「買う画面で分かる」は、上限に当たるのが加工でも起きるので不十分** —— 加工で溢れたときは `在庫上限 999 に達した` が**ログに1回流れて消える**（`GameScene.ts:709`）。**5行しかないログなので、数手で押し流される。** |
| **理由への当て方** | 「買う画面で分かる」は**買うときだけの話。**⚠ **加工で上限に当たる経路が抜けている。** |

#### 4-3. 持ち物一覧の `（売り場に出している）` を色だけにしたこと

| | |
|---|---|
| **消した理由** | 「PO 名指し。いま既に色が変わっている（`#88bbaa`）ので、**文字を消しても分かる**」 |
| **反論**（カジュアル層・やりこみ層） | ⚠ **同じ行に、意味の違う緑が2つある。**数量 `5個` は **`#88bbaa`＝棚に出している**、売値 `120レン` は **`#88bb99`＝この島が産地**（`InventoryPanel.ts:232,240`）。**別の意味なのに、隣り合って、ほぼ同じ色。**文字を消した根拠が「色で分かる」なら、**その色が2つの意味を持っている時点で根拠が崩れている。** |

#### 4-4. 工房の `材料を組み合わせて、深く作るほど取り分が増える`
