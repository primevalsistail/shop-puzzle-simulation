## D — R5・D2 が加工品に1品も当たらない

```ts
D2: condition: { axis: '産地', op: '!=', value: 'なし' }
R5: 甲/乙 とも同じ
```

**加工品70品はすべて産地 `なし`**（旬を持たないため）。よって**この2本は tier1 の50品にしか効かない。**
加工が進むほど効かなくなる。判定役は「上達するほど効かなくなる規則が2本」とした。

効かせるには「**材料を遡った産地の集合**」を導出する必要がある
（品側に産地を書き足すのは #21・#22 で却下済み。主材料を選ぶと恣意性が入るため）。
集合になるので、R5 は「集合が交わるか」、D2 は「集合が現在地を含まないか」になる。

### Question 1

A) **いま直す。**`derive.ts` に `導出産地(itemId): Set<産地>` を足し、R5・D2 の突き合わせをそれに変える
   （tier・売値と同じ**導出値**なので品側の軸は増えない）
B) **直さない。**「R5・D2 は素材にしか効かない」と定義文に明記し、issue に出して Phase 4 の後へ**【推奨】**
   理由: 集合になると条件言語に「含む」が要り、**規則の書き方が一段複雑になる**
X) Other（[Answer]: の後に記述してください）

[Answer]: B

## E — U4 が読まれておらず、U3 はデータが存在しない

`evaluate.ts` の `stockedByIslandMerchant` は

```ts
const isLocal    = item.origin === state.現在地   // U3 … rules.ts に存在しない
const isSeaborne = item.origin === 'なし'         // U4 … rules.ts にあるが読まれない
const passesTierGate  = rules.some(r => r.id === 'U1' && ...)   // IDで名指し
const passesSalesGate = rules.some(r => r.id === 'U2' && ...)   // IDで名指し
```

**問題は3つ。**
1. `U4.stockedBy` も `U4.condition` も**一度も読まれない**（評価器が同じことを再実装している）
2. `U3` は**規則データに存在しない**（評価器の中だけにある）
3. **IDで名指し**しているので、**U5 を配列に足しても無視される**

データ駆動にするには `産地 == 現在地`（軸どうしの比較）と、
`UnlockRule` に「**場所の条件**（どこで並ぶか）」と「**解禁の条件**（そもそも並ぶか）」の区別が要る。

### Question 2

A) **データ駆動にする。**条件言語に `産地 == 現在地` を足し、`UnlockRule` に区別の欄を1つ足す
   規則を足せば効くようになる（U5 が無視されなくなる）
B) **嘘を消すだけにする。**`U4` を `rules.ts` から削除し、
   「入荷の**場所**の条件は評価器が持つ。規則データが持つのは**解禁**の条件（U1・U2）だけ」と明記する**【推奨】**
   **機構は増えない。**いま存在しない「U5 を足す」も起きていない
C) **何もしない**（食い違いを記録だけ残す）
X) Other（[Answer]: の後に記述してください）

[Answer]: B

B・B なら #31 は開いたままで、**Cycle 4 は軸と規則の確定で閉じられます。**
