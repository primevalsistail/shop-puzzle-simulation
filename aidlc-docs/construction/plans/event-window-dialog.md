# できごとの窓を「ダイアログ」にする（PO 指示 2026-09-14）

## 目的

**PO 原文: 「なんか前に出てる感ないよね。ダイアログにしてもらっていい？」**

窓（`MessageWindow` ／ #24 の器）は、**盤面の上に置いた同系色の箱**でしかなく、
**背景の一部に見える。**この作りには**既にダイアログの型が2つある**ので、それに揃える。

## 決定済みの前提（議論の対象ではない）

- ⚠ **この作りのダイアログは「全画面の暗幕 ＋ 画面中央の面」**である。**2箇所とも同じ形:**
  - `Tutorial.ts:63` —— `rectangle(0, 0, width, height, 0x000000, 0.75).setInteractive()` ＋
    `rectangle(width/2, height/2, 480, 280, 0x1a1a3a)`
  - `SaveLoadMenu.ts:76` —— `rectangle(cx, cy, width, height, 0x000000, 0.65).setInteractive()` ＋
    `rectangle(cx, cy, mw, mh, 0x16213e).setStrokeStyle(2, 0x5566cc)`
  **3つ目の形を作らない。**「前に出ている」をこの作りで表しているのはこの2つだけである
- ⚠ **寸法は `src/ui/layout.ts` だけが持つ**（CLAUDE.md）。`MessageWindow.ts` に数を置かない
- **大きさは 440×120 のまま**（PO 2026-09-13「大きすぎる。余白が多すぎる」で決めたばかり）。
  **今回の指摘は大きさではなく奥行き**
- **開いている間は時間と配置が止まる。出口は選択肢だけ**（#24 の既決）。**ここは変えない**

## 今回決めないこと

- **話し手の絵**（窓に顔を出すか、キャラ帯に出すか）→ **#21 ／ #15**
- **チュートリアルとセーブ枠の暗幕の濃さが違うこと**（0.75 と 0.65）。
  **こちらは 0.65 に合わせた**が、3箇所を1つの定数にまとめるのは別の話 → **#110**

## やること

| | 直し |
|---|---|
| 1 | **全画面の暗幕を敷く**（`0x000000` ／ 0.65 ／ `setInteractive()` で下を押させない） |
| 2 | **窓を画面の中央へ移す**（`SCREEN_W/2, SCREEN_H/2`。**チュートリアル・セーブ枠と同じ**） |
| 3 | **面を不透明にし、セーブ枠と同じ色にする**（`0x16213e` ／ 枠 2px `0x5566cc`） |

### ⚠ 位置を変えると、#24 の規則のうち1つの前提が変わる

元の規則は **「納品の帯と中心をそろえる」**（PO 2026-09-13）だった。
**あれは窓が帯のすぐ上にあったときの話**で、**画面の中央へ出すなら、そろえる相手は帯ではない。**
**この作りの他の2つのダイアログはどちらも画面の中央**なので、そちらに合わせる。

⚠ **「消してはいけないものに被らない」は、位置を変えても全部そのまま成り立つ**（実測）:

| 見るもの | 中央へ移した後 | 境目 |
|---|---|---|
| 左右のパネル | x **420〜860** | 220 / 1090 |
| キャラ帯（店番・来店客） | 右端 **860** | 980 |
| 納品の帯（#28） | 下端 **420** | 590 |
| メッセージ欄 | 下端 **420** | 610 |

⚠ **暗幕は「消す」ではなく「沈める」。**#24 の既決2（**棚を消さない**）はそのまま —— 
`PlaceFrame` は棚を `destroy()` してから中央を入れ替えるが、**こちらは後ろが見えている。**

## 受入条件

1. **全画面に暗幕がかかり、下を押しても何も起きない**
2. **窓が画面の中央にある**（チュートリアル・セーブ枠と同じ中心）
3. **左右のパネル・キャラ帯・納品の帯・メッセージ欄のどれにも被っていない**ことをテストが見ている
4. **暗幕・中央・不透明**の3つを `MessageWindow.ts` が実際にやっていることをテストが見ている
   （**Phaser を読むのでソースとして縛る。**`domInput.test.ts` と同じやり方）
5. `tsc --noEmit` ／ `npm run build` ／ **全テストが通る**
6. **ブラウザで実際に出して確かめる**

---

## 結果（2026-09-14）

**3件すべて入った。****ブラウザで実際に出して確かめた**（JS エラー0件）。

- **暗幕が全画面**（`0x000000` ／ 0.65 ／ `setInteractive()`）。**左パネルも右の HUD も盤面も沈む**
- **窓は画面の中央**（`SCREEN_W/2, SCREEN_H/2` ＝ **x 420〜860 ／ y 300〜420**）
- **面は不透明**（`0x16213e` ／ 枠 2px `0x5566cc`。**`SaveLoadMenu` と同じ色**）

**「被らない」は位置を変えても全部そのまま**（実測。左右のパネル 220/1090 ／ キャラ帯 980 ／
納品の帯 590 ／ メッセージ欄 610 —— **どれにも届いていない**）。

### テスト

⚠ **`MSG_WIN_CX` が「納品の帯の中心」を指す検査を、「画面の中央」に差し替えた。**
**捨てたのは「そろえる相手」だけ**で、**被らないほうの検査4件はそのまま残っている。**

⚠ **検査を3件足した** —— **暗幕が透ける**（不透明にすると `PlaceFrame` と同じ「消す」になる）／
**盤面の上下に棚が残る**（以前は「上半分より下から始まる」で、**中央に出すと 2px 差で通る**
偶然の検査になっていた。**上下の両側を見るように書き直した**）／
⚠ **`MessageWindow.ts` が実際に「全画面の暗幕・下を押させない面が2つ・不透明な面」を
やっていること**（`?raw` でソースとして縛る。`domInput.test.ts` と同じやり方）。
**寸法だけ見ていても「前に出ている」は測れない。**
