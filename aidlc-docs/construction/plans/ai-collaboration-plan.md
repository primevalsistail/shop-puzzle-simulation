# ClaudeのAI-DLCとCodexの質問整理を組み合わせる運用

作成: 2026-09-07。調査基準: `80e203c`、ブランチ `docs/worldbuilding`。
状態: 役割と記録方法を整備済み。Claudeとの自動往復はまだ実機検証していない。

## 1. この運用の目的

ClaudeがAI-DLCで調査・設計・疑問出し・実装・テストを進める。
Codexは質問の背景とユーザーの意図を理解し、必要な調査・検算を行って回答する。
ユーザーにはプロダクト上の選択だけを分かりやすく相談する。
Claudeの設計能力やAI-DLCを置き換えるための構成ではない。

## 3. 一回の依頼の流れ

1. ユーザーがCodexへ目的と優先順位を伝える。
2. Codexは最新の状態と既決事項を調べ、目的・対象範囲・出典をClaudeへ渡す。
   Claudeが自分で調査・設計し、AI-DLCの質問を出せる余地を残す。
3. ClaudeはAI-DLCを実行し、質問票または結果を返す。
4. Codexは原文を読み、次の順序で処理する。
   - 既にPOが決めたこと: 出典と適用範囲を示して回答する。
   - コード調査・実測で答えられること: 調査・検算して回答する。
   - 技術判断: 選択肢・影響を吟味し、理由つきで決める。
   - 新しいPO判断: ユーザーに平易な言葉で相談する。
5. Codexが回答を質問番号と結びつけてClaudeへ返す。Claudeは矛盾があれば再質問する。
6. Claudeが実装・テスト。Codexが差分・受入条件・結果をレビューして必要なら差し戻す。
7. Codexがユーザーへ変更内容・検証結果・未完了事項を短く報告する。

技術的に見える質問も、ゲーム体験を変える場合はPO判断を含む。
例: 「所要時間の式をどうするか」は、単なるコード構造の話とは限らない。
Codexは数学的な妥当性を確認し、「長い加工を待つ遊びにするか」等の体験の選択に訳して相談する。
ユーザーの曖昧な回答から仕様を補った場合は、補った解釈を明示し、重大な新規選択なら確定前に確認する。

## 4. 既存文書に追記する受け渡し情報

タスクの正本は既存の対象計画。Issueがあればリンクする。
計画末尾に次を置き、Codexが進行状態を管理する。

- 目的・対象範囲・今回決めないこと・受入条件
- 基準コミット、作業ブランチ、作業場所
- ClaudeセッションID（未起動なら未起動と記載）
- 状態: 調査設計中 / Codex回答待ち / PO判断待ち / 実装中 / レビュー待ち / 完了 / 実行環境待ち
- 参照する質問票、現在の未解決質問番号、次の担当と一手
- 変更結果、テスト、Codexのレビュー、完了判定

既存質問票の質問原文は残し、各質問に以下を追記する。

```text
質問ID: Q1（既存番号を維持）
質問の狙い:
区分: 既決 / 調査 / 技術判断 / PO判断
根拠: ファイル・節・コミット、またはユーザーの発言
回答者: Codex / PO
回答:
理由と影響:
状態: 未回答 / 回答済み / 再質問
```

既存の `[Answer]` を使う場合も回答者と根拠を添える。
POの発言原文とCodexの解釈を分け、過去の監査ログを後から書き換えない。
新しい記録には実際の日時・担当者を記す。Claudeのステージ確認をCodexが処理した事実を残す。
質問を隠したり、未回答を回答済みとして実装を進めたりしない。

## 5. 直接往復の方法と現在の制約

初期方式はCodexから既存Claude Code CLIの非対話実行を呼ぶ方法。
`claude -p` のJSON結果からセッションIDと質問・結果を受け取り、
次の呼び出しは `--resume <そのID>` を指定して回答を返す。
「最後の会話」を選ぶ `--continue` は、VS Code側の別作業と取り違えるため使わない。

最初の依頼には「Codexからの委任」「AI-DLCを継続」「回答待ちなら質問を返して終了」を明記する。
AI-DLCのチェックポイントを削除せず、技術上の返答先をCodexとする。
回答が必要な質問を返した非対話プロセスはいったん終了してよい。
人間の入力待ちを維持せず、Codexが内容を判断して同じセッションを再開する。

起動ごとに作業ディレクトリを正しいLinuxパスに固定し、基準コミット・差分を照合する。
Claude実装中はCodexとVS Codeの別Claudeが同じファイルを同時編集しない。
並行作業が必要な場合だけ、現在の作業ブランチから分離したworktreeを使う。
権限は対象の読み書きと必要なテストに限定し、全権限スキップは使わない。
外側のCodex実行制限も引き続き適用する。
失敗時は終了コード、結果内のエラー、権限拒否を確認し、質問待ちと区別する。
同じ失敗を無限に繰り返さず、2回続けば原因調査に切り替える。
実行時間・費用の上限を起動前に設定し、中断時は未解決質問と再開情報を保存する。

確認済み:
- Claude Code 2.1.233がWSLに存在する。
- `claude auth status` はloggedIn=true、認証は `apiKeyHelper`。
  ChatGPTの利用枠をClaudeが使うわけではない。Claude側の契約・課金先までは未確認。
- GitHub APIからIssue一覧を取得できた。サンドボックス内の認証検査だけでは失敗したが、
  許可されたネットワークアクセスでは成功したため、認証切れと断定しない。
- CodexはLinuxパスを明示すれば読み取り可能。テストとビルドは実行範囲の承認後に成功した。
- アプリの作業パス・書き込み範囲にはまだ誤変換がある。文書の保存にも個別の実行承認が必要。

未確認:
- Claudeへの実リクエスト、AI-DLCの読み込み、質問→回答→再開の一巡。
- Claudeの編集・テスト権限と料金上限の実際の動作。
これらが確認できるまでは「自動連携が稼働済み」と報告しない。
まず読み取りだけの小さな課題で質問と再開を検証し、その後に限定的な実装で一巡させる。
初期段階では独自MCP、常駐サーバー、スケジューラーは追加しない。

## 6. 今回の変更と日常操作

追加したのは3ファイルのみ。
- `AGENTS.md`: Codexの質問整理・回答・レビューの役割。
- `CLAUDE.md`: AI-DLCを維持したまま、明示的な委任時の返却先をCodexにするルール。
  2026-09-11に「Claude内での司令塔とサブへの委任」を追記し、
  サブの疑問をmainが4区分して回答する運用を加えた。区分の原文はこのファイルに置く。
- この文書: 調査結果、記録方法、導入と検証の手順。

既存スキル、ゲームコード、既存のPO回答は変更しない。
後続で対象計画・質問票・状態文書を更新する際は、この運用を使う。
既存文書の古い記述を整理する場合は、決定の履歴と最新状態を区別して修正する。

ユーザーの日常操作は「Codexデスクトップを開き、次に作りたいものを伝える」。
Claudeからの質問をコピーして運ぶ操作は、直接往復が検証できた後は不要。
PO相談にはCodexが整理した選択肢へ回答する。技術上の回答とClaudeへの再送はCodexが担当する。
認証やOS権限など本人操作が必要な場合は、技術設計の質問とは別に理由を説明する。
既存ChatGPT Projectは企画相談と背景の保管に残す。
その会話が自動同期されるとは仮定せず、日常の開発窓口はCodexに寄せる。
別Projectで新たに決めた方針は、利用可能な接続で取得できるか確認し、取れない場合に限り
決定事項だけを共有してもらう。過去のProject全文の移し替えは要求しない。

完了条件は、受入条件を満たし、差分レビューと必要なテスト・ビルドが済み、
未実施のUI確認や残課題が明記されていること。実装済みと公開済みは分ける。
GitHubへの投稿・Issue更新・公開は、ユーザーの明示的な依頼がある範囲で行う。
