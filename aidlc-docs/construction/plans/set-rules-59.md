## 目的

**組み合わせボーナスに「隣り合っていなくてよい」という形を足す。**
**あわせて、いま3つに分かれている器を1つにする。**

いまの3つ: `PAIR_RULES`（R1〜R4・R6）／ `SAME_ORIGIN_RULE`（R5）／ `SIGNATURE_PAIRS`（空）。
**どれも「隣り合っていること」を要求する。**

---

## 決めたこと

### 1. ⚠ 甲乙の非対称は、`members` を**順序のある条件の列**にして残す

**本文の `SetRule` 案は `members` が単なる集合で、これでは既存の規則を書けない。**
**効き目は甲にだけかかる**（R4「贅沢な品の隣に日用の品を置くと**値が下がる**」で、
**日用品まで値下がりしないのはこのため**）。**集合にすると、この非対称が消える。**

> **`members` は順序のある列にする。効き目は先頭に当たった品にかかる。**

これで既存の規則がそのまま書ける:
- R1 = `members: [食料, 飲みもの]` → **食料の側が**売れやすくなる
- R4 = `members: [贅沢, 日用]` → **贅沢の側の**値が下がる
- R5 = `members: [産地 != なし, 産地 != なし]` ＋ **島が一致するかは評価器が見る**（いまと同じ）
- 名物コンビ = `members` に品 ID を並べる

### 2. `scope` は足さない

段3 で廃止した。**適用範囲は品の tier から按分される**（tier1 は 90% が店全体／tier7 は 90% がその区画）。
⚠ **`SetRule` に `scope` を戻さないこと。**

### 3. 同棚セットのデータを入れる（PO 判断 2026-09-14）

**「隣り合っていなくても、盤面に置いてあれば効く」ボーナスを入れる。**
⚠ **PO の指定は「倍率は低めでよい」。**
**理由**: このゲームは在庫の**置き方**で遊ぶもの。位置を問わないボーナスを強くすると、
**そこを考えなくてよくなる。**

⚠ **何本入れるかは多くしない。**まず**1〜2本**。軸の条件で書く（品 ID を名指ししない）。

### 4. `r.id === 'U1'` の名指しを解く（#31 からの持ち越し）

`evaluate.ts:343-344` が **`U1` と `U2` を ID で名指し**して拾っている。
**規則を足しても、ここに名前を書かない限り無視される。**

**いまの式は `passesTierGate || passesSalesGate` ＝ 「どれか1本でも通ればよい」。**
⚠ **ID で名指しする必要がそもそも無い。**
**`stockedBy` で絞ってから「どれか1本でも通るか」を見る形にする**
（`UNLOCK_RULES` はいま U1・U2 の2本とも `'島の商人'` なので、**今日の振る舞いは変わらない**）。
⚠ **これで `stockedBy` が初めて読まれる欄になる**（いまは器だけ立っている）。
