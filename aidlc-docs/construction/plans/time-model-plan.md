# 時間モデルの確定 — 実行計画（[#25](https://github.com/primevalsistail/shop-puzzle-simulation/issues/25)）

## 現状（コードを読んだ結果）

- `TimeManager` は `{day, hour, minute}` を持つだけ。**一日に区切りが無く、24時間ずっと客が来る**
- **加工中は時間が止まる**（`pause()` で `advanceMinute()` が呼ばれない）。
  プレイヤーが払っているのは**実時間の待ちだけ**で、**ゲーム内では加工のコストがゼロ**
- 加工の進行は実時間（`CRAFT_MS_PER_MINUTE`）

#25 で決まっていること:

| 時刻 | 区分 |
|---|---|
| 6:00-10:00 | 作業 |
| 10:00-20:00 | **営業**（客が来るのはここだけ） |
| 20:00-24:00 | 作業 |
| 24:00-6:00 | 睡眠（スキップして日付を進める） |

## ⚠ Question 1 — #25 と Cycle 4 が食い違っている

- **#25**: 「加工は**作業時間帯の**ゲーム内時間を消費する」
- **Cycle 4**: 「**加工している間は店が閉まる**（作る時間 ＝ 売る機会の損失）」

**前者だと加工は営業を削らないので、機会損失が発生しない。**
Cycle 4 の利幅の考え方（`利益 ÷ 加工分`）と、加工倍率の式は**すべて後者を前提**にしている。

**数で見ると**: 作業時間は 4h＋4h＝**480分/日**。
毛皮裏の外套は1回**960分**なので、**作業時間だけでは2日かかる**。
チーズ・干し肉・ぶどうの酒（各1440分）は**3日**。

A) **営業中も加工できる。加工中は店が閉まる**（Cycle 4 の前提を採る）**【推奨】**
   「作る時間 ＝ 売る機会の損失」が成立し、Cycle 4 の利幅の設計がそのまま生きる。
   **#25 の「作業時間帯の」という限定を外す**
B) **加工は作業時間帯だけ**（#25 の記述を採る）
   営業は削られない。**加工の機会損失が消えるので、Cycle 4 の加工倍率の設計をやり直すことになる**
X) Other（[Answer]: の後に記述してください）

[Answer]: A、6~10、20~24はいわゆる「客が来ない」時間。10~20は「客が来る」時間。ただし「加工中の時間は客が来ない」とする

## Question 2 — 加工中、時間はどう進みますか

いまは 100ms = 1ゲーム分。960分の加工は**実時間で96秒**待つことになります。

A) **等速のまま**（960分＝実時間96秒待つ）
B) **加工中は早送り**（終わるまで一気に進める）**【推奨】**
   長い加工で実時間を待たされない。**閉店による損失はゲーム内時間として正しく引かれる**
X) Other（[Answer]: の後に記述してください）

[Answer]: B、ゲーム内時間として算出してその分飛ばす。

## Question 3 — 日をまたぐ加工

960分・1440分の加工は**1日で終わりません**。

A) **持ち越す**（日をまたいで続く。寝ている間も進む）**【推奨】**
B) **その日のうちに終わらない加工は着手できない**（480分以下しか作れない → **長い加工品が作れなくなる**）
X) Other（[Answer]: の後に記述してください）

[Answer]: B、960や1440の加工は何らかのテコ入れが必要。

## 影響（#25 に明記されている）

- **`durationMinutes` の意味が変わる**（実時間の待ち → ゲーム内の時間）
- **営業が1日10時間に限定される**ので、客の来店ペースの基準が変わる（#11 は後で調整）
- 加工が本当のコストになるため、**取得ルートの損得が変わる**（#23）
- **[#35](https://github.com/primevalsistail/shop-puzzle-simulation/issues/35)（加工時間が長すぎる）はこの後に再測定が要る** —
  「100個で66.7日」の計算は 1日=1440分 で出しているが、**営業10時間なら意味が変わる**

## 追記 2026-09-11 — 段4 の積み残し（R-1）を修正

この計画の実装後に見つかった**表示の不具合**を直した。**仕様は変えていない。**

  **▶ を押すまで時計が古いまま**になっていた（23:55 に5分の加工をすると画面は Day1 23:55、実状態は Day2 06:00）。
  表示だけの問題で、内部状態とセーブは正しい
- **修正**: `GameScene` が `TIME_SKIPPED` を購読し、ペイロードの `time` で時計を更新する。
  売買は回さないので「**加工している間は客が来ない**」（Q1=A）は維持。
  `TIME_DAY_CHANGED` は購読しない（`time` に `day` が入っており二重更新になるため）
- **併せて**: `GameService.onMinutePassed(rng, isOpen)` の既定値を撤去して必須引数にした（渡し忘れ＝営業中扱いを防ぐ）
- **検証**: 153テスト全件パス ／ `tsc --noEmit` ／ `npm run build` 成功
