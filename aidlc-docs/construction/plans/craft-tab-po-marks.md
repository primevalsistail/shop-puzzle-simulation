# 工房の赤入れ（PO 指示 2026-09-13・画面への書き込み）

## 目的

**工房の画面に、PO が「↓のように表示して」と表を描いた。**そのとおりに直す。

原文（PO が描いた表）:

| 商品 | 作成数 | 在庫 | 時間 | 需要 | 数量 | 作る |
|---|---|---|---|---|---|---|
| そば粉 | 3 | 400 | 90分 | ノアキータ | `-10` `-1` `□` `+1` `+10` `最大` | ボタン |

**いまは1件が3段組み**（`蕎麦粉×3(400)　90分` ／ `蕎麦の実×3(400)＠ノアキータ` ／
`転売+12レン → 作る+129レン`）＋右に `− □ 回 ＋` と `最大` と `作る`。
**これを1行の表にする。**

## 決定済みの前提（議論の対象ではない）

- 原文は PO の赤入れ。**言い回しではなく「どの列を、どの順で出すか」の指示**なので、
  #79（文言は PO の領分）には当たらない
- ⚠ **表の作り方は納品タブ（`DeliveryTab`）に先例がある**（**同じ日の PO 赤入れ**）。
  **見出しの行は一覧の上に1回だけ。**列の名も位置も `layout.ts` の1箇所から来る。
  ⚠ **改装タブの Q2（見出しを行の中か上か）はまだ未回答**だが、
  **納品タブが既に「上に1回」で `main` に入っている**ので、ここはそれに揃える
- ⚠ **寸法は `src/ui/layout.ts` だけが持つ**（CLAUDE.md）。`CraftMenu.ts` に直値を残さない
- ⚠ **作れない理由はボタンの字に入れる。**商人タブ（`BUY_REASON_FUNDS`）・
  納品タブ（`deliveryShortLabel`）と同じ作り。**1行になると理由を置く段が無くなる**ため
- ⚠ **`需要` 列に出す値は「材料の産地」である。**図の `ノアキータ` は
  **いま `蕎麦の実×3(400)＠ノアキータ` に付いている `＠` そのもの。**
  **実測**: 出来上がる品の `蕎麦粉` は `suitedLand: どこでも` ／ `origin: なし` なので、
  **「売れる島」と読むと、この行は空になり `ノアキータ` は出ない。**
  → **図の値と1対1で対応するのは産地のほう。**列名だけ PO へ回す（質問票 Q1）
- **実測（列の幅を決めた根拠）**:
  **いちばん長い品名 `フェルト張りの氷入れ` = 10文字**（14px で 140px）／
  **材料の産地は最大3島**（`ハルヴェラ・リナツィア・ミフユリア`。424組中2組だけ）。
  **2島までが 121px、3島は 204px。**→ **2島までを収める幅にし、3島は `…` に詰める**

## 今回決めないこと

- **材料の一覧（`蕎麦の実×3(400)`）が行から消える。**図に列が無い。
  → **#107**（PO 判断。質問票 Q2）
- **儲け方の3ルート（#23。`転売+12レン → 作る+129レン`）が行から消える。**図に列が無い。
  → **#108**（PO 判断。質問票 Q3）。⚠ **`routeValues` は消さない**（`taxonomy` 側に残す）
- **`需要` 列の名前**（中身は産地）。→ **質問票 Q1**
- **入力欄に上限を超える数を打ったときの `時間` 列。**4桁（`9999分`）までしか測っていない。
  それ以上は `…` に詰まる。**`作る` は押せない状態なので実害は無い**

## やること

| | 中身 | 直し |
|---|---|---|
| 1 | 行を表にする | `ROW_H` 84 → 40。1件1行。**見出しの行を一覧の上に1回**（納品タブと同じ） |
| 2 | `商品` | 出来上がる品の名前だけ（`×3(400)　90分` を外す） |
| 3 | `作成数` | `outputQuantity × 回数`。右そろえ |
| 4 | `在庫` | 出来上がる品の在庫。右そろえ |
| 5 | `時間` | `craftTimeLabel(所要, 営業)`。**`（営業◯分）` は今までどおり付く**（#53） |
| 6 | `需要` | **いまここで手に入らない材料の産地**（`＠` を列にしたもの）。島名を `・` で繋ぐ |
| 7 | `数量` | `-10` `-1` `□` `+1` `+10` `最大` を1列に。**`回` の字と、別段の `最大` は無くなる** |
| 8 | `作る` | ボタン。**作れないときは字が理由に変わる**（`材料不足` `在庫上限` `時間切れ` …） |
| 9 | 行数 | `rowsThatFit` から出す。**5行 → 11行**（ページ 17 → 8） |
| 10 | 寸法 | `layout.ts` に `CRAFT_*` として置く。`CraftMenu.ts` は読むだけ |

## 受入条件

1. **工房の一覧の上に、見出しの行が1回だけ出る**（`商品 作成数 在庫 時間 需要 数量 作る`）
2. **1件が1行**である。3段組みが残っていない
3. **`-10` `-1` `□` `+1` `+10` `最大` が1列に並ぶ。**`回` の字が出ない
4. **作れないとき、`作る` ボタンの字が理由に変わる**（4通り）
5. **列が重ならない**ことをテストが見ている ——
   最長の品名 ／ 4桁の作成数・在庫 ／ `9999分（営業600分）` ／ **2島ぶんの産地** ／
   いちばん長い理由の字が `作る` ボタンに収まること
6. **工房の寸法が `layout.ts` の1箇所だけにある**（`CraftMenu.ts` に直値を残さない）
7. **1ページに 11行入り、最後の行がページ送りに食い込まない**ことをテストが見ている
8. `tsc --noEmit` ／ `npm run build` ／ **全テストが通る**
