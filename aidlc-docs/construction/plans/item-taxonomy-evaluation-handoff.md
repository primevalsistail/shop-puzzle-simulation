# アイテム体系の評価 — 検討依頼

**このファイルだけで判断できるように書いてある。他の資料は要らない。**

ゲームのアイテム体系を作り直し、**110品と規則を書き終えた**ところ。
**それが妥当かの判定をお願いしたい。**

**書いた本人は判定しない**という取り決めになっている。書いた側が判定すると、
偏りが出たときに品を差し替えて偏りを消してしまい、判定が自己採点になるため。
**したがって以下には、書いた側の所見も、合格ラインも書いていない。**
何をもって合格とするかも含めて、そちらで決めてほしい。

---

# 1. 何を作ったか

**在庫配置パズル型の店舗経営シミュレーション。**
気候の違う四つの島を10日ごとに巡る店舟で、船倉に品を並べて売る。
船倉は升目になっていて、品はテトリスのように場所を取る。隣り合わせに置くと効き目が出る。
**加工している間は店が閉まる**（作る時間 ＝ 売る機会の損失）。

アイテムは **5本の軸**で表す。

| # | 軸 | 問い | 値 |
|---|---|---|---|
| 1 | 主種類 | これは何であるか | `食料` `飲みもの` `衣類` `道具` |
| 2 | tier | どれだけ加工されているか | 1〜4（**レシピから導出**。手書きしない） |
| 3 | 産地 | どの島で採れるか | 四島 ＋ `なし` |
| 4 | 贅沢さ | 客がどれだけ奮発して買うか | `日用` < `上等` < `贅沢`（順序あり） |
| 5 | 向く土地 | どんな土地で役に立つ品か | `寒い土地` `暑い土地` `温暖な土地` `実りの土地` `どこでも` |

**四島**（増減しない）: ハルヴェラ（温暖）／ リナツィア（陽が強く暑い）／
ノアキータ（実りが絶えない）／ ミフユリア（雪が絶えない）

**島の需要**は4行だけ。「向く土地が今いる島の気候と合う品は売れやすい」を4島ぶん書いたもの。

```
向く土地=='寒い土地'   かつ 現在地=='ミフユリア'  → 売れやすさ ↑
向く土地=='暑い土地'   かつ 現在地=='リナツィア'  → 売れやすさ ↑
向く土地=='温暖な土地' かつ 現在地=='ハルヴェラ'  → 売れやすさ ↑
向く土地=='実りの土地' かつ 現在地=='ノアキータ'  → 売れやすさ ↑
```

**入荷解禁**: 島の商人が並べるのは**素材（tier1）だけ**。
加工品は**作るか**、その品を100個売って**解禁する**かのどちらか（解禁後は買えるが、作るより高い）。

---

# 2. 判定してほしいこと（5件）

**この5件は、体系を設計した段階で「あとで確かめること」として挙げられたもの。**
各項目が何を意味するかは書いてあるが、**どこからが「まずい」かは書いていない。**

### 検査1 — `道具` に何品入っているか
主種類4値のうち `道具` だけが後から分割される可能性のある値として扱われている。
**多すぎるなら分割を検討する。**

### 検査2 — `向く土地` が `どこでも` に偏っていないか
`どこでも` の品には島の需要（上の4行）が効かない。
**`どこでも` が多いほど、島を巡る意味と、島ごとの品揃えの違いが薄くなる。**

### 検査3 — 産地 `なし` の割合
`なし` の品は**どの島でも買える**。**多すぎると、島を巡らなくても品揃えが揃ってしまう。**
少なすぎると、島を1つ外したときに詰む。
**なお加工品は全部 `なし` である**（理由は §5）。この設計の是非も含めて見てほしい。

### 検査4 — `主種類4 × 贅沢さ3` の12通りに品が散っているか
片方に寄っているなら、**軸が余っている**（その軸が品を区別できていない）可能性がある。

### 検査5 — 「その品を100個売ると買えるようになる」の 100 という数
**100 は仮に置いた数。**

---

# 3. 判定の枠組み

偏りが見つかったとき、**原因は2通りある。どちらかを切り分けてほしい。**

| 原因 | 意味 | 対応 |
|---|---|---|
| **軸の設計の問題** | 軸そのものが品を区別できていない／値の切り方が悪い | **軸の設計に戻る**（大きい手戻り） |
| **品の起こし方の問題** | 軸は妥当だが、110品の選び方が偏っていた | 品を足す・入れ替える（小さい手戻り） |

**この切り分けがこの依頼の本体。**

### この先へ進んでよいか
次の工程は「**新しい品30個と新レシピ10本を投げ込んで、体系が壊れるか見る**」ストレステスト。
**上の5件の結果しだいでは、そこへ進まずに軸の設計に戻るべきかもしれない。**どちらにするかを決めてほしい。

---

# 4. 書いた側が把握している「判断の揺れ」

**隠すと判定が歪むので、開示する。**いずれも**まだ誰も解決していない。**

`向く土地` を振ったセッションが、振り終えたあとに自ら申告したもの。

1. **保存食6品**（塩鮭・干し肉・チーズ・ジャム・いわしのオイル漬け・バター）が `どこでも` に落ちた。
   `実りの土地` の「蓄える」を「蓄える**手段**（塩・容れ物）」に限定して読み、
   「蓄えた**結果**」を外したため。**結果まで含めれば `実りの土地` は5品から11品に増える。**
   この線は定義文に書かれていない
2. **温かい飲食8品**（スープ・グラタン・レモンの茶・蜂蜜の乳ほか）を `寒い土地` に入れてよいか。
   定義は「**熱を守る**」＝断熱の言葉で、熱いスープは熱を**与える**もの。
   この読みを外すと **`寒い土地` は16品から8品に減る**
3. **生魚5品**（まぐろ・いわし・いか・鮭・かに）。`温暖な土地` の例示に「生鮮」があるので
   素直に読むと全部 `温暖な土地` になる。**「四島すべての海で獲れるので土地と結びつかない」**
   という理由で `どこでも` にしたが、これは定義に書かれていない条件
4. **「持ち歩くために作られた品」と「結果として持ち歩ける品」**の区別（おにぎり vs 干し肉）は
   定義文にない。くるみのビスケットは半分は勘で `温暖な土地` に置いた
5. **用途が広すぎる素材5品**（竹・革・帆布・オリーブ・蜜蝋）。
   どれか一つの用途を選べば別の値に振れてしまうので `どこでも` に置いた。
   **`どこでも` のうち相当数が「土地を選ばない」ではなく「土地を一つに選べない」である**

---

# 5. 産地について — 加工品はすべて `なし`

産地は「**その品が一般的にどの季節のイメージか**」だけで決めている。
四島は春・夏・秋・冬にあたる気候がそれぞれ一年じゅう続く土地なので、
**旬が春の品はハルヴェラ、夏ならリナツィア、秋ならノアキータ、冬ならミフユリア。
旬を持たない（通年の）ものは `なし`。**

**加工品は旬を持たないので、すべて `なし`。**
「主材料の産地」を採らなかったのは、四島＋海にまたがる品でどれが主材料かを決められず、
**恣意的な選択が入る**ため。

**島を巡る理由はレシピが担っている** — 60本中49本が2島以上の材料を使い、
**四島＋海すべてにまたがるレシピが5本**ある。

**加工倍率は手で決めていない。**次の式で機械的に置いている。

```
craftMultiplier = 1.30 + 0.25 × min(所要分 / 480, 2) + 0.15 × 贅沢さの順位
```

「加工倍率を所要時間**だけ**から決めると `利益/時間` が全品一定になり、
何を買ってどう売っても結局同じになる」という設計上の警告への対応。
**品ごとの手当ては1件も入っていない。**

# 7. 検査を走らせたい場合

コードは `src/taxonomy/` にある。`ALL_ITEMS`（items.ts）と `ALL_RECIPES`（recipes.ts）を
読めば上の表と同じものが取れる。`derive.ts` に `tier()` `salePrice()` `dumpAll()` がある。

```
npm test          # 既存101 + 新規41 = 142テスト（すべてパスしている状態）
npx tsc --noEmit
```

**すでに通っている検査**（＝ここでは判定しなくてよい）:

| | 内容 |
|---|---|
| 追加しても既存が変わらない | 品やレシピを1件足しても、既存品の属性（導出値を含む）が1つも動かない |
| 導出できる属性を持たない | 型に `tier` も `price` も無い。レシピから計算している |
| 規則がアイテムを知らない | 条件規則にアイテムIDが1つも出てこない。ID を書ける層は空にしてある |
| 追加コストが定数 | 品を1つ足すのに書くのは定義1件だけ。既存は1行も変わらない |
| 作った品は材料より高い | 全60レシピで `売値(出力) × 出力数 > Σ売値(材料)` |
