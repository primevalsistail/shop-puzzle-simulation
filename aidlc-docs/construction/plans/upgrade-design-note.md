# 強化要素の設計メモ（棚・客・単価・セット）

**作成**: 2026-09-11
**きっかけ**: PO提案「4系統の強化を入れ、**100万＝全機能最大開放で10〜20日**にしたい」
**位置づけ**: 束D（利益率）の途中で出た設計相談。**実装はまだしていない。**
**関係する issue**: #5（棚の拡張）／ #11（客が来る）／ #12（購入金額）／ #54（利益率）／ #52（到達が早い）

## 1. 賛成する点 — 3つの強化は**既にある3軸とちょうど一致する**

`evaluate.ts` の `Modifiers` は **`集客` ／ `売れやすさ` ／ `値段`** の3つ。
提案の3系統はこれに1対1で対応する。

| 提案 | 既にある軸 |
|---|---|
| 来店客を増やす | `集客`（店全体） |
| 購入されやすさを増やす | `売れやすさ` |
| 客が払う金額を増やす | `値段` |

**新しい概念を1つも足さずに済む。**偶然ではなく、Cycle 4 で効き目を3軸に整理したため。

### ⚠ ただし「同じ輪」に入れてはいけない

効き目の合成は**加算**（`combine` = `1 + Σ(mᵢ − 1)`）。取り合わせ R1 は **1.2倍（+0.2）**。
ここに強化の **+2.0** を混ぜると、**配置の工夫が誤差になる。**

**強化は加算の輪に入れず、別の掛け算にする。**

```
最終倍率 ＝ 配置の倍率（規則の加算） × 強化の倍率
```

こうすれば「強化で底上げしつつ、配置の工夫は常に効く」という形になる。

## 2. いちばん大きい問題 — **いまの初期値では強化が効かない**

**無強化・6×5 のいまで、すでに所持金100万に 23日で届く。**
「全開放で10〜20日」にすると、**全部の強化を合わせた効果が 1.2〜2.3倍**にしかならない。

4系統を何段階も積んで2倍では、**1段階あたり数%。買った実感が出ない。**

### 結論: **初期を弱くするのが先。強化の設計はその後。**

終盤で日商（利益）¥50,000〜100,000 なら10〜20日で届く。
初期を日商 ¥3,000〜5,000 に置けば、**強化の総合倍率は 15〜25倍**になり、1段階ごとに手応えが出る。

### 実測: **束D の Q2「客1人1個まで」を選ぶと、ちょうどそこに着地する**

| | 日商（利益） | 100万まで |
|---|---|---|
| いま（区画15・全区画を独立判定） | ¥42,290 | 23日 |
| 区画12（6×5 の実際の区画数） | ¥12,496 | 81日 |
| **＋ 客1人1個まで（販売個数 0.27倍）** | **約 ¥3,400** | 約294日 |
| ＋ 強化を全部（下の配分で17.6倍） | **約 ¥60,000** | **約17日** |

**「初期は294日かかるが、全開放すれば17日」＝ 強化が必須ルートになり、かつ効き目が体感できる。**

### 総合倍率 17.6倍 の配分案（掛け算）

| 強化 | 倍率 | 根拠 |
|---|---|---|
| 棚の拡張（12区画 → 32区画） | **2.6倍** | 実測。区画数にほぼ線形 |
| 来店／売れやすさ | 3倍 | 置き値 |
| 払う金額 | 1.5倍 | 置き値 |
| セット販売 | 1.5倍 | 置き値 |
| **合計** | **17.6倍** | |

⚠ **棚の 2.6倍だけは実測値。**他の3つは「17倍に収まるように割った」置き値で、根拠はまだ無い。

## 3. 目標と強化費が**同じ通貨**でぶつかる

クリアの基準は**所持金100万**（#26 の確定事項）。**強化も所持金で買う。**

- **終盤に強化を買うと目標が遠のく** → 回収する日数が残っていないので、誰も買わない
- つまり**強化は自然と「序盤に買うもの」**になる

### 「全機能最大開放」を前提にするなら、強化は**選択ではなく段階**

ユーザーの言う「全機能最大開放で10〜20日」は、**全部買えることが前提**。
その場合、**どれを買うかの判断は無く、どの順で買うかの判断だけ**が残る。
これは悪くないが、**「取捨選択させたい」なら総額を稼げる額より大きくする必要がある**（両立しない）。

### 強化費の総額をいくらに置くか

- **総額を目標の30〜50%（30〜50万）** に置くと、全開放には **130〜150万**稼ぐことになる
- **1割以下**だと、強化は経済的な判断ではなく**ただの段階解放**になる
- **目標を超える**と、全開放が不可能になる（＝取捨選択のゲームになる）

## 4. 「セットで販売」は**2種類に分かれる。片方は新機構**

| 案 | いまの器 | 判定 |
|---|---|---|
| **隣接**で特定の組を並べる | **層2（`SIGNATURE_PAIRS`）が既にある。既定は空** | **書けば終わり。新機構ゼロ** |
| **N種同時販売**（隣接でなく、店に揃っていれば） | **無い** | **条件言語に「盤面の集合に対する条件」が要る** |

N種同時は #31（軸どうしの比較）とも #37（含む）とも**別の新しい種類**。
**隣接だけで狙いが satisfied されるなら、そちらを強く推す。**

⚠ 層2 は「**全部消しても層1だけで成立する**」という不変条件（INV-4）で作ってある。
セット販売をここに載せるのは設計どおりの使い方。

## 5. 盤面の刻み — 画面は足りる。ただし**伸び率が後半で落ちる**

### 画面の制約

グリッド領域は **x 228〜1090 ／ y 8〜609**、1升 58px。
→ **最大 14×10 まで入る。高さが先に尽きる。**9×9 は余裕がある。

### 提案の刻みと区画数（品の平均は 2.48升）

| 盤面 | 升 | 区画 | 前段からの伸び |
|---|---|---|---|
| 6×5 | 30 | 12 | — |
| 6×6 | 36 | 14 | +17% |
| 7×6 | 42 | 16 | +14% |
| 7×7 | 49 | 19 | +19% |
| 8×7 | 56 | 22 | +16% |
| 8×8 | 64 | 25 | +14% |
| 9×8 | 72 | 29 | +16% |
| 9×9 | 81 | 32 | +10% |

**升目の増分は一定だが、区画の伸び率は 17% → 10% に落ちる。**
後半ほど「広げた感」が薄い。気にするなら**後半を大きく刻む**（9×8 の次を 11×9 にする等）。

### ⚠ 序盤は**置く品のほうが足りない**

各島の商人が売る前に並べるのは **16〜19品**。

- **7×7（19区画）までは1島の品だけで埋まる**
- **8×7（22区画）以上は、加工するか、島を回って買い溜めないと埋まらない**

**これは良い圧力。**盤面の拡張が「加工しろ」「島を回れ」と言う装置になる。
十分売れば各島90品前後まで解禁され、4島の和集合は **122品（全部）**。**品不足で詰むことはない。**

⚠ ただし在庫は999持てるので、**買い溜めが正解になりやすい**。

## 6. こちらから勧める順序

1. **束D で初期の売れ行きを決める**（Q1・Q2）。**ここが全部の分母**
2. **強化の総合倍率を決める**（初期日商 × 倍率 = 終盤日商 → 目標日数）
3. **4系統に倍率を配分する**（棚の2.6倍だけは実測。他は配分）
4. **強化費の総額を決める**（目標の何割か）
5. 実装。**セット販売は隣接だけなら層2に書くだけ**

**⚠ 2〜4 を決めずに実装に入ると、値を置く根拠が無いまま122品と8段階ぶんの数字が増える。**
Cycle 4 の `item-system.md` §8 が戒めた「数値を出すのが早すぎた」の再発になる。
