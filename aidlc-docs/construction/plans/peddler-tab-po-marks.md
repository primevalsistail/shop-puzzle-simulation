### 5・6 の原因（実測 2026-09-13・ヘッドレス Chrome）

**`<input>` は `tryAddDom(x, y, ...)` に「中心」を渡している。**Phaser の `DOMElement` は
**要素を `getBoundingClientRect()` で測り、その半分を引いて中心合わせにする。**

⚠ **ところが `<input>` を作る時点で DOM コンテナが `display: none` になっている。**
できごとの窓・チュートリアル・セーブ画面を出している間は
`setDomInputsVisible(scene, false)` でまとめて隠す作りで、**行商人はそのできごとの窓から開く。**
**隠れている要素の `getBoundingClientRect()` は 0×0** なので、
**中心合わせのオフセットが 0 のまま焼き付き、左上が指定点に来る。**

**実測**: 検索欄は中心 (982, 90) のつもりが**左上が (982, 90)**。
右端が `CONTENT_R`(1062) を **70px 突き抜けて HUD に被る。**
個数欄も同じで、**右へ 26px ずれて `＋` に重なる。**

⚠ **併せて、欄の実寸が指定より小さい。**`index.html` の `* { box-sizing: border-box }` が効くのに、
`createInput` は `width: ${w - 10}px` と content-box 前提で書いてある。
**検索欄は 160×24 のつもりで 150×18。**

**直し**: **`tryAddDom` に左上を渡し、`setOrigin(0, 0)` で置く。**
こうすると**測った大きさを使わない**ので、隠れていようがいまいが同じ場所に出る。
併せて `createInput` に `box-sizing: border-box` を明示し、`width`/`height` をそのまま使う。

⚠ **`<input>` を置く4箇所すべてが同じ罠を踏む**（持ち物の検索・仕入れの検索・仕入れの個数・
工房の回数・マイセットの名前）。**`domInput.ts` の1箇所で直す。**

### ついでに直したもの

- ⚠ **`<input>` の実寸が指定と同じになった。**`index.html` の `* { box-sizing: border-box }` と
  `createInput` の `width: ${w - 10}px` が食い違っていて、**検索欄は 160×24 のつもりで 150×18 だった。**
- ⚠ **`SEARCH_W` / `SEARCH_H` の写しを消した。**`PurchaseMenu.ts` と `CraftMenu.ts` が
  **同じ 160×24 を別々に持っていた。**`layout.ts` の `LIST_SEARCH_W` / `LIST_SEARCH_H` が唯一の出どころ。
- ⚠ **検査を6件足した** —— 検索欄が枠を越えない／主種類のボタンに重ならない／絞り込みの行に収まる／
  個数欄が `−` `＋` のあいだに収まる（`layout.test.ts`）、
  `tryAddDom` が左上基点である／欄の実寸が頼んだ大きさと同じ（`domInput.test.ts`）。
  **それまで `<input>` の場所は1つも見ていなかった**（HTML なので Phaser 側のテストに何も出ない）。
