# #123 ロード前にゲーム画面が表示される

## 目的

**「つづきから」を押した直後にゲーム画面（1日目）が見えてしまうのを止める。**
タイトル → ロードの枠を選ぶ → 選んだ状態のゲーム画面、の順にする。

## いまの姿（原因）

`TitleScene` の「つづきから」が `GameScene` を `{ openLoad: true }` で始めている。
`GameScene.create()` が**1日目の画面を丸ごと組み上げてから**、末尾で `saveLoadMenu.openLoad()` を呼ぶ。
枠を選ぶ前に、ゲーム画面が背後に見えている。

## 決定済みの前提（PO 回答 2026-09-15。原文は `audit.md`）

1. **枠3つはタイトル画面の上に重ねる**（専用の絵は作らない）
2. **枠を押したあとの確認（「読み込む／やめる」）は残す**
3. **「キャンセル」はタイトルへ戻る**（= 枠の面を閉じてタイトルのまま）
4. **ゲーム内（⚙️ → ロード）は据え置き**（いま遊んでいる分が消えるので確認も残す）

## 今回決めないこと

- ロード画面用の絵・文言（Q1 案C は不採用）
- セーブデータの形式（`SaveData` は触らない）
- タイトル画面の題名・顔・ボタンの配置

## やること

1. `GameProgress.ts` に**インスタンス無しで枠を読む関数**を出す
   （`readSlotMeta(slot)`。`hasAnySave()` と同じ理由 —— タイトル側には `GameProgress` の一式が無い）
2. `TitleScene` が `SaveLoadMenu` を**自分の上で**開く。`GameScene` は作らない
   - `onLoad(slot)` → `scene.start('GameScene', { loadSlot: slot })`
   - キャンセル → 面を閉じるだけ（タイトルが残る）
3. `GameScene` の `startMode` を `{ fresh?, loadSlot? }` にする（`openLoad` は消す）
   - 中に埋まっているロードの手順を `applyLoad(slot)` として切り出す
   - `create()` の末尾で `loadSlot` があれば `applyLoad` を呼ぶ。
     **同じフレーム内なので、1日目の画面は一度も描かれない**
4. `SaveLoadMenu` に**キャンセルの行き先を渡せる口**を足す（ゲーム内は今までどおり閉じるだけ）

## 受入条件

- タイトルの「つづきから」で、**ゲーム画面が一瞬も出ずに**枠3つが出る（背後はタイトル）
- 枠を押すと確認が出て、「読み込む」でその記録の状態のゲーム画面になる
- 「やめる」で枠の一覧へ、「キャンセル」でタイトルへ戻る
- 記録が1つも無ければ「つづきから」は押せない（今までどおり）
- ゲーム内の ⚙️ → セーブ／ロードの動きが変わらない
- `npx vitest run` 全件パス ／ `npx tsc --noEmit` が通る
