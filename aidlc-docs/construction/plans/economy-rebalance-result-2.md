### ⚠ §2 の判定（依頼書がいう唯一の合格判定）

> **入れ替わった。**「1万円あたり何日縮むか」の1位が、場面によって
> **手際・棚・来客頻度・利益率の4つの間で入れ替わる。**
> **序盤は手際が1位**（安くて加工の取り分が6割あるため）、
> **盤面が育つと棚・来客・利益率に移る。**

**⚠ ただし「仕入れ」だけは、正面からは勝たない。**
仕入れが1位になるのは**他が買えないときだけ**で、買える強化があるときは常に強化のほうが速い。
運転資本が効いていないわけではない —— 9×8 の盤面を ¥8,000 で回すと日次利益は
**¥9,599 → ¥7,005（−27%）**に落ちる。**効いてはいるが、順位までは覆さない**（§10-7）。

**島でも入れ替わらない**（日次利益は 1.0〜1.5倍ぶれるが、順位は同じ）。

### main に判断してほしいこと（§10 に詳しく）

1. **⚠ tier3・tier4 のレシピは、3案のどれを採っても死んだまま**（§6-5）。
   原因は加工の速度ではなく **`PROFIT_EXPONENT = 0.6`**。

2. **加工の取り分は 37% で頭打ち。**50%超にするには `PROFIT_EXPONENT` か作業時間480分に触る（§10-2）
3. `SPEED_FLOOR` を 0.25 → 0.05 にしてよいか（§6-2）。**`craft.ts` の定数1つ。データ変更ゼロ**
4. **集客の上限を 8.0 に置く**提案（§10-4）。実測の到達上限は 6.9〜7.8 なので**いまの遊びは削らない**

## 2. ⚠ §2 の判定 — 取捨選択になっているか（**第2版の測定**・投資先は5択）

> ⚠ **この節は床0.25・手際S10→22 のまま測った第2版の数字である。**
> 床を 0.05 にすると作業効率の終盤の効き目が大きく上がる（§6-3）ので、
> **⑥⑨のような終盤の場面では作業効率の順位が上がるはず**だが、**測り直していない**（§10-6）。

**測り方**: 各時点で「これ以上は強化を買わない」と決めたときの**100万までの残り日数**を出し、
`(何も買わない場合の日数 − その手を打った場合の日数) ÷ 費用` を比べた。
**「仕入れ」は所持金を資本のまま持つこと**とし、資本を1割増やしたときの日数の縮みで測った。

⚠ **測り直しで1つ直したこと**: 手際を上げると `craft.ts` の clamp は必ず良くなる（単調）のに、
貪欲探索は候補の並びが変わると**低い手際のほうが良い盤面を見つける**ことがあった。
**S 以下の全段で見つけた盤面を、いまの S の表で評価し直して最良を採る**ことで単調性を保証している。
これをしないと手際の価値が**負に出る**（実際に踏んだ）。

|---|---|---|---|---|---|---|

**1位になった投資先は4種類 — 手際・仕入れ・来客頻度・利益率。**
棚は per-yen では1位にならないが、**②④⑦⑧ では「残り日数がいちばん縮むのは棚」**で、

### 入れ替わりを起こしている4つの理由（どれも機構から出ている）

1. **⚠ 手際は「盤面が加工しているとき」だけ効く**（第2版で見つけた最大の入れ替わり）。
   ⑥（13×10・加工22%）では **+20.0日/万**、⑦⑧（7×6・加工0%）では **−2.0日/万**。
   同じ ¥5,000 が、盤面次第で得にも損にもなる。
   加工の取り分が大きい**序盤ほど手際が強い**（①② で1位）のも同じ理由
2. **運転資本が要るかどうか** — 棚と来客は**1日の仕入れ額を同じ倍率で増やす**。
   利益率と手際は増やさない。13×10 の1日の仕入れ額は **¥16,137**、来客×3 で **¥45,310**。
   → **金欠のとき（③）は「何も買わずに棚を埋める」が1位**
3. **置くものがあるかどうか** — 序盤は商人が **18〜19品**しか並べない。
   同じ「棚1段」が、一周する前（6×5→13×10 で **1.21倍**）と後（**9.7倍**）で8倍違う。
   ⑤（6×5・手際最大）では **棚を買っても 0.00日**（置くものが無い）
4. **どれが伸びしろを残しているか** — ⑦⑧ が対称形。来客を最大にすると利益率が1位、
   利益率を最大にすると来客が1位

### ⚠ 「仕入れ」が1位になるのは、他が買えないときだけ

③ は所持金 ¥8,000 で、いちばん安い手際 S16（¥10,000）にも届かない。
**届く場面では、仕入れは常に負ける。**

| | ③ 所持金 ¥8,000 | ④ 所持金 ¥80,000 |
|---|---|---|
| 9×8 の1日の仕入れ額 | ¥12,049 が要る | 同左 |
| 日次利益 | **¥7,005** | **¥9,599** |

**運転資本は日次利益を 27% 動かしている**が、来客×2 の 16.7日/万 には届かない。
**強化の回収が速すぎる**からで、費用をさらに上げれば仕入れが正面から勝つ場面を作れる。
ただしそれは「強化が買えないゲーム」に近づくので、**推奨しない**（§10-7）。

### ⚠ 「1万円あたり」と「残り日数」が食い違う場面がある（②④⑦⑧）

②では**手際が1万円あたりで1位**だが、**棚を買ったほうが残り日数は344日短い**（577日 vs 921日）。
④でも棚が **55日 vs 86日** で最良。
これは「安いものを今すぐ買う」と「高いものを貯めて買う」の対立で、
**取捨選択としてはこちらのほうが本体**だと考える。どちらを推奨表示にするかは UI の設計判断。

### ⚠ 入れ替わらなかったもの — 島

同じ段・同じ所持金で4島を比べると、**順位は4島とも同じ**だった（日次利益だけが 1.0〜1.5倍ぶれる）。

| 島（6×5・無強化・S10・その島の品だけ） | 仕入れ可 | 日次利益 | 加工の取り分 |
|---|---|---|---|
| ハルヴェラ | 18品 | **¥1,576** | 60% |
| ノアキータ | 19品 | ¥1,266 | 53% |
| ミフユリア | 18品 | ¥1,094 | 61% |
| リナツィア | 16品 | **¥1,029** | 26% |

差は需要表（`DEMAND_TABLE` の 1.3）ではなく**その島の材料で作れるレシピの本数**から来ている。
**島は「稼ぎの上下」を作るが「何を買うか」の判断は変えない**（§10-5）。

## 3. やること1 — 来店率・素の購入確率

### 提案

```
CUSTOMER_ARRIVAL_RATE   0.3  →  0.04
BASE_PURCHASE_PROB      0.4  →  0.06
1人が買う個数の上限      入れない（§1の決定）
```

### なぜこの値か

**(a) 上限を入れないので、「1人が何個買うか」は棚の広さで決まる。**そこを見て決めた。

| | 客/日 | 個/日 | **個/客** |
|---|---|---|---|
| 6×5・無強化・ハルヴェラ初日 | 62 | 54 | **0.87** |
| 13×10・無強化・買い溜め済み | 182 | 524 | **2.88** |
| 13×10・全開放 | 547 | 1,509 | **2.76** |

**「1人が1つ買っていく店」から始まり、棚を広げると「ついでにもう2つ買う店」になる。**
上限を入れない決定の意味がここに出る。`0.06` より上げると序盤から 2個/客 を超え、
下げると棚を広げても 1個/客 のままになる。

**(b) 来店率 0.04 は「1分あたり1人」の天井から逆算した。**
来店判定は `arrival × 店全体の集客 × 来客頻度` で、**1を超えたぶんは捨てられる**（毎分必ず1人）。
実測で店全体の集客は R5 で **最大 7.6倍**まで伸びるので、

```
0.04 × 7.6 × 3.0（来客最大） = 0.91  … 天井のすぐ下
```

**0.05 にすると全開放で天井に当たり、来客頻度の最後の1段が無価値になる。**

## 4. やること2 — 利益率の初期値

### 提案: `TIER1_PURCHASE_RATE` **0.5 → 0.7**（`PROFIT_SCALE` は 5.6 のまま触らない）

実測（来店率0.04・素の購入確率0.06・6×5・ハルヴェラ初日・資本無限。**売れる個数は54個で変わらない**）

| 買値率 | 日次利益 | 1日の仕入れ額 | 加工の取り分 |
|---|---|---|---|
| 0.5（いま） | ¥2,112 | ¥1,198 | 51% |
| 0.6 | ¥1,847 | ¥1,428 | 55% |
| **0.7（提案）** | **¥1,576** | **¥1,661** | **60%** |
| 0.75 | ¥1,420 | ¥1,797 | 64% |
| 0.8 | ¥1,378 | ¥1,899 | 64% |

**0.7 にする理由は3つ:**

1. **同じ利益を出すのに必要な運転資本が増える。**粗利が売値の50%から30%に薄くなるので、
   ¥1 の利益に必要な仕入れが ¥1.0 → ¥2.3 になる。**§2 で「仕入れ」が投資先として立つのはこのため。**
   0.5 のままだと所持金が常に余り、仕入れの判断が消える
2. **加工の取り分が上がる。**作った品の粗利は `材料費×(1−買値率) + 加工利益` なので、
   買値率を上げると「安く買って素で売る」ぶんだけが薄くなり、加工利益は残る
3. **0.8 まで上げると生売りがほぼ無利益になり**、「仕入れて並べる」が判断でなくなる

### ⚠ `PROFIT_SCALE` を触らなかった理由

前回は 5.6 → 12.5 を提案していたが、**今回は触らなくても加工の取り分が序盤 60% に届いた**
（前回との差は、来店率をさらに下げたことと買値率0.7）。
`PROFIT_SCALE` は72レシピの利益に一様に掛かる倍率で、**比は動かないが経済の規模は動く。**
触る理由が無いので触らない（`keep-it-simple`）。**終盤の加工の取り分を上げたい場合はここが唯一の倍率**（§10-2）。

### 6-5. ⚠ いちばん大事な発見 — **tier3・tier4 が死んでいるのは速度のせいではない**

**3案のどれを採っても、使われるのは tier2 のレシピだけだった。**S=30・床0.05 でも変わらない。

原因は `derive.ts` の **`PROFIT_EXPONENT = 0.6`**:

```
加工利益 P = PROFIT_SCALE × (所要分/出力数)^0.6 × 贅沢さ係数
→ 分あたりの利益 P/分 ∝ 所要分^(0.6 − 1) = 所要分^(−0.4)
```

**所要分が長いほど `¥/分` は単調に下がる。**速度の倍率は全品に同じ係数として掛かるので、
**どんな速度体系を入れても、この順位は絶対に動かない。**実測:

| 品 | tier | S=30・床0.05 での1個あたり | 加工利益 ¥/分 |
|---|---|---|---|
| いちごのかき氷 | 2 | 0.4分 | **80.0** |
| バター | 2 | 4.5分 | 24.9 |
| 蕎麦粉のパン | 3 | 16分 | 7.7 |
| 羊毛の敷物 | 3 | 38分 | 10.5 |

→ **`aidlc-state.md:54` の却下理由「一律の速度倍率なので品どうしの `利益/時間` の順位が変わらない」は、
案②だけでなく、いま採っている S−D 方式にも等しく当てはまっていた。**
S−D の clamp は **tier どうしの所要時間の比**を動かすが、
**`¥/分` の順位は `PROFIT_EXPONENT` が先に決めてしまっている。**

**つまり (e) の答え: 却下理由は問題として現れるが、案②だけの問題ではない。
3案を分ける根拠にはならない。**分けるのは (a) 加工の取り分と (d) 実装の重さだけ。

⚠ `problem-a-verdict.md` の検算1(ii)「失う営業分の折れ線があるから順位は動く」は、
**本文の測り方では効いていない。**本文は「加工は作業時間480分の中だけで行う」と仮定しており、
営業を削る選択肢を与えていないため。**加工の ¥/分（最良16〜80）が営業の ¥/分（終盤 ¥176/分）を
下回るので、営業を削って加工する動機はどのみち生じない**（実測）。

## 10. main に判断してほしいこと

### 10-1. 来客頻度と利益率は、**式の上ではいまも同じ倍率**である（main の回答を反映済み）

どちらも日次利益に線形に掛かる。**違いは2つだけ:**

| | 来客頻度 | 利益率 |
|---|---|---|
| 1日の仕入れ額 | **同じ倍率で増える**（13×10 で ¥16,137 → ¥45,310） | **増えない** |
| 天井 | **1分あたり1人**（600人/日）で頭打ち | 無し |

**main の回答（受領済み）: 値段を上げると客が減る、という代償は足さない。**
実測でも順位は運転資本で入れ替わっており（§2 ⑦⑧）、機構を増やさずに取捨選択は成立している。
費用に2〜3割の差をつけて交互に1位が来るようにしてある。

⚠ ただし**手際が加わったことで、この2系統が「どちらも同じ」に見える場面は減った。**
§2 ⑥ では手際が3位（+20.0）に食い込み、①② では1位。**4系統のうち2つが同型でも、
残り2つが性質の違う軸（升目・時間）なので、盤面全体としては区別がついている。**

### 10-2. 加工の取り分は **37% で頭打ち**。50%超には別のものが要る ⚠（第3版で更新）

| | 加工の取り分（終盤） |
|---|---|
| 第1版（手際を強化に入れていない） | 6% |
| 第2版（手際 S10→22・床0.25） | 18% |
| **第3版（手際 S10→30・床0.05）** | **37%** |

**50%超には届かない。**天井は `480分 × 最良の¥/分 × 利益率倍率` で、
床0.05 でも **1日 ¥38,400 × 利益率3.0** が上限。13×10 の店は1日1,500個を売る。

| 手 | やること | 代償 |
|---|---|---|
| A **37% で手を打つ**【サブの推奨】 | 何もしない | 「序盤は加工が6割、終盤は4割」。**加工は最後まで主役の一角に残る** |
| B `PROFIT_EXPONENT` を 0.6 → 0.8 前後に上げる | `derive.ts` の1行 | **長いレシピの `¥/分` が上がり、tier3・tier4 が初めて選択肢になる**（§6-5）。⚠ **72品の相対関係が全部動く。**Cycle 4 が釣り合わせたパレートフロンティア（14品）を測り直すことになる |
| C 作業時間480分を増やす | 時間モデル | **`what-this-game-is.md` §3「加工に使える時間は増やせない（いまのところ）」に触る** |

**⚠ プレイヤーの体験が変わる**（終盤に「何を仕込むか」を考え続けるかどうか）ので **PO判断**。
**B は §6-5 の tier3・tier4 問題と同じ1本のつまみ**なので、両方を一度に解ける唯一の手でもある。

### 10-3. 棚の最終段 — **PO が決着（Q2 = B）。費用表は安くしない**

> 最後の1段は**2周目・エンドレス用**でよい。「高くて後でいいな」という判断につくのも正着。

→ **第2版で提案した値下げ（¥120,000 → ¥100,000）は据え置き、それ以上は下げない。**
強化の総額 ¥559,000 のうち通しで買われるのは 7割前後だが、**仕様として受け入れる。**
§2 ⑨ の「終盤に高い買い物をすると目標が遠のく」も、経済として正しい挙動なので直さない。

### 10-4. 集客の上限 — **8.0 を提案**（第3版。main の「天井を外す」は取り下げ済み）

**R5 が加算・上限なしなので、店全体の集客は盤面が広いほど伸びる。**実測（産地を持つ素材43品を
産地ごとに固めて置けるだけ置いた、集客を最大化する並べ方）:

| 盤面 | 置けた品 | **店全体の集客** | 来店確率（来客×3.0 のとき） |
|---|---|---|---|
| 6×5 | 18 | 3.50 | 0.420 |
| 7×6 | 23 | 4.00 | 0.480 |
| 8×7 | 30 | 4.70 | 0.564 |
| 9×8 | 36 | 5.70 | 0.684 |
| 11×9 | 42 | 6.70 | 0.804 |
| **13×10** | **43（全部）** | **6.90** | **0.828** |

（貪欲に最適化した盤面では 7.6〜7.8 まで出る。**産地を持つ素材が43品しかないので、
そこが事実上の上限**になっている。）

**提案: `shopWide.集客` の上限を 8.0 に置く。**

```
来店率 0.04 × 集客上限 8.0 × 来客頻度上限 3.0 = 0.96 < 1.0
```

- **1分1人の頭打ちが構造的に起きなくなる。**買った来客頻度の段が無駄になることがない
- **実測の到達上限（6.9〜7.8）より上なので、いまの遊びを1つも削らない。**
  「並べ方の価値 2.59倍」（§8）はそのまま残る
- **升目・集客・作業効率・利益率の4つがすべて有限**になり、PO の言う非対称が消える

**別案: 上限 5.0。**9×8 以上で実際に頭打ちになるので「並べ方にも天井がある」ことが
プレイヤーに見える。⚠ ただし **13×10 の日次利益が 2〜3割落ちる**ので、
棚の総合倍率（9.7倍）と費用表を測り直すことになる。**サブは 8.0 を推す。**

### 10-5. 島は「稼ぎの上下」を作るが「判断」は変えない（スコープ外の申し送り）

§2 のとおり島で投資先の順位は入れ替わらなかった。日次利益の差（¥1,029〜¥1,576）は
需要表ではなく**その島の材料で作れるレシピの本数**から来ている。
**島ごとに違う遊び方をさせたいなら、触るのは `DEMAND_TABLE` ではなくレシピの材料構成。**
前回の申し送り（`economy-rebalance-result.md` §11-2）と同じ結論に、別の測り方で着いた。

### 10-6. 測り方の限界（そのまま鵜呑みにしないこと）

- **棚の埋め方は貪欲の近似。**R5 が絡むと局所解に落ちやすいので、種を3本（空／島の棚を先に作る／
  作れる品を先に並べる）走らせて良い方を採っている。それでも**実際の上手いプレイヤーより低めに出ている**可能性がある
- **⚠ 手際については単調性を後から強制している**（§2 の冒頭）。これをしないと
  「手際を上げると損」という有り得ない結果が出る。**貪欲が手際の価値を取りこぼす**ということなので、
  本文の手際の効き目も**低めに出ている**と見てよい
- **⚠ §2 と §7 は床0.25 のまま測った第2版の数字で、床0.05 では測り直していない。**
  §6-3 のとおり作業効率の終盤の効き目が 1.29倍になるので、
  **終盤の場面（§2 ⑥⑨）では作業効率の順位が上がり、通しの67日は 60日前後に縮む見込み。**
  **ここは次に測る**
- **航海日（1,080分）の作り溜めを織り込んでいない。**到達日数は数%短くなる方向に振れる
- **9×8 のあたりで「加工の取り分が 0%」になる場面がある**（§2 ③④）。
  買い溜めで122品が使えるようになると生売りの選択肢が増え、**加工品に区画を割く価値が一時的に消える。**
  盤面がさらに広がると（13×10）区画が余って加工が戻る。**この谷が本物かどうかは遊んで確かめたほうがよい**

### 10-7. 「仕入れ」を正面から勝たせるか（技術判断だが、体験が変わる線の上にある）

いまの費用だと、**買える強化があるときは必ず強化が勝つ**（§2）。
仕入れが1位になるのは「まだ買えない」場面だけで、
プレイヤーから見ると「**貯める → 買う → また貯める**」の繰り返しになる。
運転資本は日次利益を 27% 動かしているが、**順位を覆すほどではない。**

| 案 | やること | 影響 |
|---|---|---|
| A **このままにする**【サブの推奨】 | 何もしない | 仕入れの判断は「1位を争う」ではなく「**強化を買った翌日に棚が埋まらない**」という形で出る |
| B 強化の費用を全体に 2〜3倍にする | 費用表 | 仕入れが正面から勝つ場面が出るが、**強化を買える回数が減る** |
| C 買値率をさらに上げる（0.7 → 0.85） | `TIER1_PURCHASE_RATE` | 必要な運転資本が倍になる。ただし**生売りがほぼ無利益になり、仕入れの判断そのものが消える**（§4） |

**⚠ B は体験が変わる**（「強化を買い集める遊び」から「資金繰りの遊び」に寄る）ので **PO判断**。

### 10-8. ⚠ tier3・tier4 のレシピは、**速度をどういじっても死んだまま**（第3版で判明）

第2版では「手際の上限 22 は `SKILL_MAX = 30` と食い違う」と書いたが、
**正体は `SPEED_FLOOR = 0.25`** だった。床を 0.05 に下げれば S=30 まで効くので、**この食い違いは消える。**

**しかし、床を下げても・工数÷加工値にしても・出力数を上げても、
使われるのは tier2 のレシピだけだった**（§6-1 の全15通り）。

原因は `derive.ts` の **`PROFIT_EXPONENT = 0.6`**:

```
加工利益 ∝ 所要分^0.6   →   ¥/分 ∝ 所要分^(−0.4)
```

**所要分が長いほど `¥/分` は必ず下がる。**速度の倍率は全品に同じ係数として掛かるので、
**速度体系を何に変えても順位は動かない。**

これは `aidlc-state.md:54` に残る却下理由
「一律の速度倍率なので品どうしの `利益/時間` の順位が変わらない」が、
**案②だけでなく現行の S−D 方式にも等しく当てはまっていた**ということ。
**S−D の clamp は tier どうしの所要時間の比を動かすが、`¥/分` の順位は
`PROFIT_EXPONENT` が先に決めてしまっている。**

| 案 | やること | 影響 |
|---|---|---|
| A **放置する**【サブの推奨】 | 何もしない | **tier3・tier4 の62本は「作れるが割に合わない」まま。**加工の判断は tier2 の中だけで起きる |
| B **`PROFIT_EXPONENT` を 0.8 前後に上げる** | `derive.ts` の1行 | **長いレシピが初めて選択肢になる。**10-2 の加工の取り分も同時に上がる。⚠ **72品の相対関係が全部動く**ので、Cycle 4 が釣り合わせたパレートフロンティアを測り直す |
| C レシピ側の `durationMinutes` / `outputQuantity` を振り直す | 72本の手書き数値 | **根拠なく動かすことになる**（`item-system.md` §8 の再発） |

**⚠ プレイヤーの体験が変わる**（重いレシピを仕込む遊びが存在するか）ので **PO判断**。
**B は 10-2 と 10-8 を1本のつまみで同時に解く唯一の手**なので、次に測るならここを推す。
