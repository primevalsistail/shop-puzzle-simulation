## 0. まずこれを読む

**[what-this-game-is.md](../../inception/design-log/what-this-game-is.md)（第3版）**
PO が4回訂正して確定したゲームの構造。**ここに書いてあることは議論の対象ではない。**

要点だけ再掲:

- **資源をやりくりして再投資を繰り返す経営ゲーム。**配置パズルは升目という制約を作る装置
- **時間を使うのは加工だけ。**仕入れも配置も0分（`skipMinutes` を呼ぶのは `CraftingSystem.startCraft` だけ）
- **金で買う長期の強化は3系統 — 棚の広さ / 来客頻度 / 利益率**
- **組み合わせボーナスは強化ではない。**買うものではなく、**気づいて並べるもの**
- 勝利条件は**所持金100万レン**

**判断の構造:**

```
金      … 今日の仕入れ（その日に返る）  ←→  強化3系統（何十日も先に返る）
加工時間 … 480分/日（航海日1,080分）をどのレシピに割くか
並べ方   … 組み合わせボーナス（金も時間も要らない）
```

## 1. main が決めたこと（前提。動かさない）

| | 決定 | 理由 |
|---|---|---|
| 棚の段階 | **5段。6×5 → 7×6 → 8×7 → 9×8 → 11×9 → 13×10** | [shelf-and-set-design.md](shelf-and-set-design.md)。1段 ×1.34 |
| 来客頻度・利益率の段階 | **同じく5段** | 系統ごとに段数が違うと比べにくい |
| 客1人の購入数 | **上限を入れない。来店率だけ下げる** | 上限を入れると拡張の価値が 1.97倍→1.23倍に落ちる。**拡張は長期投資の柱なので殺せない** |
| 強化費用 | **段が進むほど高くする**（PO指定） | |
| 強化の倍率 | **配置の倍率とは別の掛け算**（加算の輪に入れない） | R1 は1.2倍。強化を加算に混ぜると配置が誤差になる |
| 加工を営業中に禁じるか | **禁じない** | 供給が売れ行きを下回るので動機が生じない |
| 目標 | **所持金100万**。PO は「**全機能最大開放で10〜20日**」と言っている | |
| 開始 | **所持金5,000／羊の乳・りんご・蕎麦粉のパン 各15個／6×5** | 実装済み |

`finalPrice` の tier1 も粗利にだけ倍率 ／ クリア判定を所持金に ／ `craft.ts` の手際を配線（PO Q2=B）。

## 2. ⚠ 今度いちばん大事なこと — **「取捨選択になっているか」を測る**

**第1次では測っていなかった。**日数・個数・利益率ばかり測り、
**「同じ1円をどこに投じるのが得か」が場面によって入れ替わるか**を一度も見ていない。

**これが唯一の合格判定:**

> **同じ1円の最適な投資先（仕入れ／棚／来客頻度／利益率）が、
> 場面（日数・所持金・盤面の広さ・島）によって入れ替わること。**

**常に1つが正解なら、値が間違っている。**

測り方の例（これに縛られなくてよい）:
- 各時点で「1円を仕入れに回した場合」と「強化を買った場合」の**残り日数の差**を出す
- 序盤・中盤・終盤で**順位が入れ替わるか**を見る
- 入れ替わらないなら、**どの値を動かせば入れ替わるか**を探す

## 3. やること

1. **来店率・素の購入確率**の具体値（「売れすぎ」を直す。ただし購入数の上限は使わない）
2. **利益率の初期値**（強化で上げる前の値。`TIER1_PURCHASE_RATE` など）
3. **強化3系統 × 5段**の**倍率**と**費用**（費用は逓増）
4. **加工が割に合う**ことの確認（作業時間480分の価値 vs 仕入れに同じ金を回した場合）
5. **§2 の合格判定** — 投資先の順位が場面で入れ替わることを示す。入れ替わらないなら値を直す
6. **到達日数**: 無強化 ／ 全機能最大開放（PO の「10〜20日」に対してどうか）
7. **組み合わせボーナスの規則を数本書いてみる**
   （[shelf-and-set-design.md](shelf-and-set-design.md) §2 の `SetRule` 案。**隣接1本・同棚1本**は必ず含める。
   効き目の倍率がどれくらいなら「並べ方を考える理由」になるかを実測で示す）

## 4. 受入条件

1. 1〜7 すべてに**具体的な数値**と**その値にした理由**がある
2. **実測で裏づける**（`src/` をそのまま回す。`npx vite-node` でスクリプトを書ける。`src/__tmp/` に置き、**終わったら消す**）
3. **測定の前提を書く**（何を仮定したか。変えると結果がどう動くか）
4. **§2 の判定結果を必ず書く**（入れ替わったか、入れ替わらなかったか。後者なら何が足りないか）
