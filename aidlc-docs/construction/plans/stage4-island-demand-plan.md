# 段4 — 島ごとの需要と、滞在中の解禁（実行計画）

**位置づけ**: [policy-rework-plan.md](policy-rework-plan.md) の段4 ／ **作成**: 2026-09-12 ／ main
**方針**: [what-players-should-do.md](../../inception/design-log/what-players-should-do.md) 6

## 目的

方針6「**島ごとに需要を変えることで、取捨選択を繰り返させる**」をコードに落とす。
「**こっちの島では〜を売る／そのためにあっちの島では〜を買う**」の往復を作る。

## 決定済みの前提と出典

| 前提 | 出典 |
|---|---|
| 島は4つ・順路は固定・**10日ごとに寄港**（1周40日） | `islands.ts` ／ PO 決定 |
| **島と品を結ぶのは需要表4行だけ。**品は島の名前を知らない | `islands.ts` `DEMAND_TABLE` |
| **バランス調整はこの4行に集まる。**品を足して数を揃えない | `islands.ts` の注記 ／ #39 |
| 滞在中の解禁の粒度は**系統単位**、頻度は**1寄港あたり2〜3回** | PO 決定 |
| 「タグ」は既存の軸だけ。**新しい属性を足さない** | PO 回答 |
| 効き目は**その品の tier で按分**される（段3） | `rules.ts` `shopWideWeight` |

### いまの姿（実測 2026-09-12）

```
寒い土地   × ミフユリア → 1.3   （該当 18品）
暑い土地   × リナツィア → 1.3   （該当 16品）
温暖な土地 × ハルヴェラ → 1.3   （該当 32品）
実りの土地 × ノアキータ → 1.3   （該当 11品）
```

**⚠ 「該当品数の偏りが歪み」という #39 の読みは、実測で外れた**（→ [stage4-demand-measure.md](stage4-demand-measure.md)）。
11品でも32品でも実効倍率は **1.26〜1.29倍**。段3 で店全体ぶんを区画数で割る形にしたので、
棚がその土地の品で埋まっていれば**品数も tier も打ち消し合う**。

**本当の歪みはプールの値段の偏り**（平均売値 寒259 / 暑200 / 実り163 / 温暖129）。結果:

**ハルヴェラでは、前の島の `寒い土地` の棚を持ち込んだほうが 6〜7% 儲かる。**
1.3倍をもらった `温暖な土地` の棚が負ける。**1島で方針6 が逆を向いている。**

**合わない品は等倍で、減らない。**だから島が変わっても並べ替える理由が弱い。

### 4-3・4-4 の結果（サブ ／ 2026-09-12）

→ [stage4-unlock-result.md](stage4-unlock-result.md)

- **条件は「材料を1つ残らず手にしたことがある」**。`Inventory.everHeld` を読む。
  「1つでも」だと `塩` を手にした時点で tier3・tier4 のほとんどが開き、**段が消える**
- **系統 ＝ 出力品の `主種類` × `tier`**（実データで12群、段5 の tier7 で24群）。
  **新しい属性は足していない。**`主種類` だけだと4群しかなく、しかも材料を持っていない tier4 まで開く
- **頻度は `UNLOCK_INTERVAL_DAYS = 4` ÷ `DAYS_PER_PORT = 10` から出る**（2.5枠 → 3回・2回が交互）。
  回数を別に書かない。**日付だけの関数**なので、解禁が無かった頃のセーブも読んだ日に追いつく

### main が引き取った判断

| | 決定 | 理由 |
|---|---|---|
| 「買えるようになった」側の知らせ | **段4 では入れない → #60** | 品揃えは毎回その場で出しており、**「増えた」差分を誰も持っていない**。覚える場所を決めるのは別の設計 |
| `CraftingSystem.canCraft` に解禁を見させるか | **見させない** | `craft()` を呼ぶのは `CraftMenu` 1箇所だけ。**解禁はプレイヤーが触る入口の話**で、材料と時間の計算に混ぜると真実の出どころが2つになる |
| **12群が Day45 で尽きる**こと | **このまま。段6 で測り直す** | 頻度は PO 指定「1寄港2〜3回」から出た値。段5 の24群で Day93。⚠ **200日のうち後半は解禁が何も起きない**ので、段6 の測り直しで扱う |
| `GameScene.ts` をサブが触ったこと | **是とする** | `CraftMenu` の生成も日付変化の受けもそこにしかなく、配線できない。変更は import・フィールド1つ・呼び出し4箇所のみ |
