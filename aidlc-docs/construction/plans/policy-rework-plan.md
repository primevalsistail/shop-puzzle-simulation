| 前提 | 出典 |
|---|---|
| 200日程度／目標は切りのいい数字（**1000万**）／到達時に全開放でなくてよい | 方針1・2・4 |

| **島ごとに需要を変える**ことで「この島で売るためにあの島で買う」を繰り返させる | 方針6 |

### main が引き取った技術判断

| | 決定 | 理由 |
|---|---|---|
| `SPEED_FLOOR` | **0.25 のまま。S を30まで刻む** | 床を下げると低tierだけが速くなり、**高tierを潰す**（実測: S=30・床0.05 で tier2 が tier4 の2.5倍）。床0.25・S=30 なら全tierが clamp に当たって横並び |
| 集客の上限 | **8.0** | 実測の到達上限（13×10 で 6.9〜7.8）より上。いまの遊びを削らない |
| 区画の巡回順 | **ランダム化** | 見えない「置いた順」が売れ行きを決めてしまう |
| `finalPrice` の tier1 | **粗利にだけ倍率**（`買値 + (売値−買値) × 倍率`） | いまは tier1 だけ売値全体に乗り、生売りを不当に強くしている |
| クリア判定 | **累計売上 → 所持金** | #26 の実装漏れ |
| 値段に対する客の反応 | **代償を足さない** | 機構を増やさずとも順位は入れ替わる |

## 今回決めないこと

- **`PROFIT_EXPONENT`（0.6）は動かさない。**深さの報酬は**ボーナス構造（方針5）で作る**
- **強化費と目標額の最終値** — 需要表・買値率の確定後に測って決める
- **組み合わせボーナスの「同棚」条件**（`SetRule`）の実装 — 段3で扱う

（いま tier3・4 の40本が一度も作られないのと同じことが起きる）。
