## 決めたこと（main が判断。サブは問い直さない）

### 1. ⚠ ウィンドウを出すのは「選択肢があるとき」だけ

**選択肢の無い知らせはログへ**（いまどおり）。**ウィンドウは選択を求めるときだけ出す。**

**理由**: #24 の既決「**飛ばせない会話を周期的に発生させない。配置パズルの手が止まる**」。
**読むだけの知らせでウィンドウを出すと、手が止まる回数がそのまま増える。**

### 2. ⚠ ウィンドウは「行く場所」（`PlaceFrame`）にしない

`PlaceFrame` は**棚を消してから**出る器で、**中央の領域がまるごと入れ替わる。**
**選択肢1つ出すために店の風景を消さない。**

⚠ **先例がある** —— `MessageLog` の遡りも**同じ理由で `PlaceFrame` にしなかった**
（「ログを読むだけで店が止まるのは重い」。`MessageLog.ts` の注記）。

### 3. ⚠ 開いている間は時間と配置を止める。判定は `isShelfBlocked()` **1つだけ**

選択を求めている以上、時間は止める。
⚠ **`GameScene.isShelfBlocked()` に足すこと。別の場所に `||` を書かない。**
**以前は同じ判定が7箇所に散らばり、1箇所だけ強化メニューが抜けていた。**

### 4. イベントはデータで書く。器に品 ID も相手の名前も埋めない

**イベントを1本足すのに、発火の仕組みを触らなくてよいこと。**
⚠ **規則（`SET_RULES` ／ `UNLOCK_RULES`）と同じ考え方。**
⚠ **`r.id === 'U1'` のような ID 名指しを、評価の側に書かないこと**（#59 で解いたばかり）。

### 5. 誰が喋っているかは**名前だけ**出す

**絵は後から入れる**（PO 判断 2026-09-14。→ #21・#15）。
⚠ **絵が無いことを理由に構造を変えない。**後から絵を差せる形にしておく。

### 6. 行商人の来訪をランダムにする（#90）

- **来るかどうかをランダムにする**（最大1日1回）。⚠ **確率は仮置き → #61 に1行足すのは main**
- **時間を進めている最中に発生させる**
- ⚠ **「行く場所」のボタン列から外す**（`GameScene.ts:476`）
- **来たらウィンドウを出し、「見る」で品揃えを開き、「断る」で閉じる**（PO 判断 2026-09-14）
