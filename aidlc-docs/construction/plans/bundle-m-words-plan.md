# 束M — 画面に出す言葉（実行計画）

**位置づけ**: [issue-grouping.md](../../inception/plans/issue-grouping.md) の束M ／ **作成**: 2026-09-12 ／ main
**対象**: **#68**（情報が多すぎる & 足りない）→ **#1**（文言を世界観に合わせる）

## 目的

**画面に出す文字を、まず減らし、それから世界観の言葉に置き換える。**

⚠ **順番が逆にならないこと。**先に言い換えると、**あとで消す文字を世界観に合わせる**ことになる。

## ⚠ この束は「自分が足したものを削る」

**#68 で PO が名指しした4つのうち3つは、束F で main が足したもの。**

| PO が挙げたもの | 出どころ |
|---|---|
| `(売り場に出している)` → 要らない | 段2.5（`55a7160`） |
| アイテムリストの**仕入れ値** → ここに表示する内容ではない | 段4-6 |
| `ハルヴェラの商人のところ` → 要らない | **#58**（`8feedd8`） |
| `この島でしか買えない…` → 要らない | **#33**（`e58bb65`） |

⚠ **足したときの理由を守りにいかないこと。**
どれも「無いと分からない」と考えて足したが、**4つ並ぶと読めなくなる**という指摘である。
**理由が正しくても、量が多ければ機能しない。**

## ⚠ 判断基準を先に決める（これを決めずに着手しない）

基準が無いと、**足したときと同じ好みで削ることになる。**
#68 本文の指定はこれ:

> **どこで何を見たいか or 見るべきか**をベースに過剰な情報を整理削減する

→ **画面ごとに「そこで下す判断」を1行書き、その判断に要らない文字を消す。**

| 画面 | そこで下す判断（案。**PO に確認する**） |
|---|---|
| 売り場（棚） | **どこに何を置くか。**何が売り切れているか |
| 持ち物一覧 | **何を棚に出すか。**いくつ持っているか |
| 商人のところ | **何をいくつ買うか** |
| 工房 | **何を何回作るか** |
| 改装 | **いま買うか、目標まで我慢するか** |
| 品出しの型 | **どの型を呼ぶか** |

⚠ **「あると便利」は消す側に倒す。**判断に要るかどうかだけで決める。
⚠ **消した理由を1行ずつ残す。**残さないと、次に誰かが同じものを足し直す。

- **色**（→ #56。**束I**）／ **解像度**（→ #10。同）／ **アイコンの画像化**（→ #69。同）

## 受入条件

1. `npx vitest run` 全件パス ／ `npx tsc --noEmit` ／ `npm run build`
2. **画面ごとの「そこで下す判断」が1行ずつ書いてある**（消す根拠として）
3. **消した文字は、消した理由つきで一覧になっている**
4. **`¥` が UI に1つも残っていない**（`レン` に統一。⚠ `grep` で確かめる）
5. **「取り合わせ」が画面に出ている**（いまは内部名だけ）
6. ⚠ **満たせないもの**: 実機での目視 → **#47 に追記**
