## 判断してほしいこと

**加工の取り分は 37% で頭打ちです。**「終盤も加工を主役に（50%超）」には届きません。

### 原因が1つに絞れました

`derive.ts` の **`PROFIT_EXPONENT = 0.6`**。

```
加工利益 ∝ 所要分^0.6   →   ¥/分 ∝ 所要分^(−0.4)
```

**所要分が長いほど時間あたりの儲けは必ず下がる。**速度の倍率は全品に同じ係数で掛かるので、
**どんな速度体系を入れても順位は動きません。**

実測でもそのとおりで、**3案15通りのどれでも、使われたのは tier2 のレシピだけ**でした。
**tier3・tier4 は一度も選ばれません。**（`SPEED_FLOOR` を下げると**本数は 2 → 7 に増える**が、
増えるのは tier2 の中だけ）

⚠ **これは `aidlc-state.md:54` の記録が間違っていたことも意味します。**
工数÷加工値を却下した理由「一律の速度倍率なので品どうしの順位が変わらない」は、
**いま採用している手際S にも等しく当てはまっていました。**却下の根拠になっていませんでした。

### 選択肢

| | やること | 得られるもの | 代償 |
|---|---|---|---|
| **A. 37% で手を打つ**【推奨】 | 何もしない | 序盤6割・終盤37%。**加工は最後まで効き続ける** | **主役（50%超）にはならない。tier3・tier4 は死んだまま** |
| **B. `PROFIT_EXPONENT` を 0.6 → 0.8 前後に上げる** | `derive.ts` の1行 | **加工が主役になる道が開く。tier3・tier4 問題と同じ1本のつまみ**で両方一度に解ける | ⚠ **72品の相対関係が全部動く。**Cycle 4 で測ったパレートフロンティア（14品）を**測り直すことになる** |

**推奨は A。**理由は2つ:

1. **B は Cycle 4 の成果を測り直す作業を呼び込む。**`PROFIT_EXPONENT = 0.6` は
   「利益の開きを 186倍 → 約10倍に縮め、升目の幅6倍と釣り合わせる」ために選ばれた値で、
   ここを動かすと**その釣り合いから測り直し**になります
2. **37% でも加工は死んでいません。**序盤6割・終盤37%で、**最後まで効き続けます。**
   「主役」という言葉に届かないだけです

**ただし B を選ぶ理由もあります** — **tier3・tier4 の30品が一度も使われない**のは、
122品を作った労力に対して大きな取りこぼしです。**そこを取りに行くなら B。**

⚠ **いま別途調べさせていること**: **航海日（1,080分・機会損失ゼロ）が長いレシピの居場所に
なっていないか。**なっていれば、**`PROFIT_EXPONENT` に触らずに tier3・tier4 を生かせる**かもしれません。
**その結果を待ってから決めても構いません。**
