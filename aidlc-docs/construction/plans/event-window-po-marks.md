# できごとの窓が大きすぎる（PO 指示 2026-09-13・画面への赤入れ）

## 目的

**行商人バレンの窓（`MessageWindow` ／ #24 の器）に PO が赤で枠を入れ、
「大きすぎる。余白が多すぎる。」と書いた。**窓を中身の大きさまで詰める。

## 決定済みの前提（議論の対象ではない）

- ⚠ **寸法は `src/ui/layout.ts` だけが持つ**（CLAUDE.md／`layout.ts` 冒頭）。
  `MessageWindow.ts` に数を置かない
- **実測（直す前）**: 窓は **748×160px**。中身は**話し手1行・本文1行（`船に寄った`）・
  ボタン2つ（160px 幅）**しかない。**本文は2行ぶん場所を取っているが、1行しか使っていない**
- **`PlaceFrame`（行く場所）にしない**（#24 の既決）。棚は消さない。ここは変えない
- **納品の帯・メッセージ欄・キャラ帯を覆わない**。ここも変えない

## 今回決めないこと

- **文言そのもの**（`船に寄った` `見る` `断る`）→ **#79（文言は PO の領分）**
- **話し手の絵**（窓に顔を出すか、キャラ帯に出すか）→ **#21 ／ #15**
- **窓の位置を動かすこと**。下端（納品の帯の上）は今までどおり

## やること

| | 指摘（原文） | 直し |
|---|---|---|
| 1 | **大きすぎる** | **幅 748 → 440**（帯と**中心**をそろえ、帯より狭くする）／**高さ 160 → 120** |
| 2 | **余白が多すぎる** | 内側の余白 20 → 14／行送り 24 → 22／ボタン 160×34 → 110×30 |

⚠ **「帯と左右をそろえる」を捨て、「帯と中心をそろえる」に替える。**
元の規則は「同じ領域に幅の違う箱を2つ並べない」ためだったが、
**帯の幅にそろえる限り、横の余白は絶対に消せない**（本文は5文字、ボタン2つで332px）。
**中心をそろえれば、幅が違っても軸は1本のまま。**

⚠ **本文に使える行数（`MSG_LINES_MAX`）は今までどおり高さから導く。**決め打ちにしない。
**高さを詰めた結果、入る行数は 2 → 1 になる。**いまのできごとは1行なので足りる。
**2行のできごとを足した日は `layout.test.ts` が落ちる。落ちたら高さを1行ぶん上げる。**

## 受入条件

1. **窓が帯より狭く、帯と中心がそろっている**
2. **本文の行を余らせていない**（`MSG_LINES_MAX` ＝ いまあるできごとの最大行数）ことを
   テストが見ている。**余白が戻ったら落ちる**
3. **幅も余らせていない**（選択肢3つぶん＋余白より、ボタン1つぶん以上は広くない）ことを
   テストが見ている
4. 話し手・本文・ボタンが今までどおり重ならず、窓からはみ出さない
5. `tsc --noEmit` ／ `npm run build` ／ **全テストが通る**
6. **ブラウザで実際に窓を出して確かめる**

---

## 結果（2026-09-13）

**2件とも入った。**`tsc --noEmit` ／ `npm run build` ／ **647テスト全件パス**（645 ＋ 足した2件）。
**ブラウザで実際に窓を出して確かめた**（JS エラー0件。`見る` から行商人の画面まで通した）。

| | 直す前 | 直した後 |
|---|---|---|
| 窓 | **748 × 160** | **440 × 120**（面積は **39%**） |
| 内側の余白 | 20 | 14 |
| ボタン | 160 × 34 | 110 × 30 |
| 本文に取ってある行 | **2行**（使うのは1行） | **1行** |

**足した検査2件**（どちらも「余白が戻ったら落ちる」ためのもの）:
- **本文の行を余らせていない** —— `MSG_LINES_MAX` ＝ いまあるできごとの最大行数。
  **2行のできごとを足した日はここが落ちる。**そのとき `MSG_WIN_H` を 22px 上げる
- **幅が、選択肢3つぶん＋余白より広すぎない** —— ボタン1つぶん以上余っていたら落ちる
