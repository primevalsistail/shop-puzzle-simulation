# #60 実装計画 —「買えるようになった」を知らせる

**束F の5件目** ／ 上位計画: [bundle-f-places-plan.md](bundle-f-places-plan.md) ／ **作成**: 2026-09-12 ／ main

## 目的

段4-4 で「**作れる**ようになった」（レシピの解禁）は知らせるようにしたが、
**「買えるようになった」（仕入れ側）は静かに品揃えへ入るだけ**で何も出ない。

PO 決定は「**滞在中にも解禁が起きる（買えるようになった・作れるようになった）**」なので、**片肺のまま。**

## 実測した現在地（2026-09-12・コードから）

### 仕入れ側の解禁は2本だけ（`rules.ts: UNLOCK_RULES`）

| 規則 | 条件 | 進むか |
|---|---|---|
| **U1** | `tier == 1` | **進まない。**素材は最初から並ぶ |
| **U2** | `tier >= 2` かつ `累計販売数（この品） >= 100` | **これだけが進む** |

→ **知らせるべき出来事は U2 ただ1つ**。「その品を100個売った瞬間」である。

### だから「前回の品揃え」を覚える必要はない

issue の但し書きにこうある:
> 差分を出すには「前回この島で並んでいた集合」を覚える必要がある。
> ⚠ `WorldState` に持たせるか、評価器に持たせるかで置き場が変わる
> U2 は「その品を100個売ると買えるようになる」ので、**売った瞬間に知らせる**ほうが素直かもしれない

**後者を採る。**売った瞬間なら、**覚えるものがゼロ**で済む
（`sale.qtySold` があるので「売る前の数」は引き算で出る）。
→ **`WorldState` にも評価器にも状態を足さない。セーブも変わらない。**

### 島は関係ない（実測）

**tier2以上の85品は、産地がすべて `なし`**（加工品は旬を持たないため）。
U4「産地を持たない品はどの島でも並ぶ」に当たるので、**どの島にいても並ぶ。**
→ 知らせに島の条件は要らない。⚠ **これはデータの形に依存するのでテストで固定する。**

### log が埋まらないか

段4-4 の知らせは**系統単位**（1本ずつ流すと埋まるため）。
**U2 は1品につき生涯1回**しか起きず、売れるのは1分に1件ずつなので、
**同時に2品が届くことはない。**→ **1品ずつ流してよい。**

## ⚠ しきい値（100）を書き写さない

`100` は**規則データの中の値**（`rules.ts` の U2）。
知らせる側に書き写すと、**規則を変えたときに知らせだけが古い数のままになる。**

→ **売る前と売った後で規則そのものを評価して、通り方が変わったかを見る。**
