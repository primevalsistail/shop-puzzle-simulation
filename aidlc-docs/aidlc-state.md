- ⚠ **イベントの窓は「行く場所」（`PlaceFrame`）にしない。**あれは**棚を消してから**出る器。
  **選択肢1つのために店の風景を消さない。**⚠ **先例: `MessageLog` の遡りも同じ理由で場所にしなかった**
- ⚠ **イベントを1本足すのは `STORY_EVENTS` に1件書くだけ**（`components/progress/StoryEvents.ts`）。
  **発火（`StoryEventScheduler`）も `GameScene` も触らない。**
  結末に新しい語が要るときだけ `StoryOutcome` に足す —— **書き忘れると `tsc` が指す**（`never` の網羅）
- ⚠ **右パネルの「行く場所」は `取引` と `工房` の2つだけ**（#96）。
  **`取引` の中が 商人・改装・納品 の3タブ。**⚠ **タブは `PlaceFrame` の見出しの行に置いてある** ——
  **下に1行足すと一覧の上端が28px下がり、仕入れが8行→7行に減る**
- ⚠ **行商人はイベント。ボタン列には無い**（#90）。**最大1日1回・ランダム・営業中に来る。**
  ⚠ **積荷は来ない日も引いている**（来訪の側で引くとロード経由で引き直せるため）
- ⚠ **納品のミッションも「1日に1回しか引かない」で持っている**（#98）。
  **島を無くしたので、歯止めはこれだけになった** —— 元は「納品先で買えない品から選ぶ」だった。
  ⚠ **引いた日を `SaveData.orderDay` に積むこと。**積まないと**欲しい依頼が出るまでロードし直せる。**
  ⚠ **外れた日も、上限10件に達した日も「引いた」ことにする** ——
  しないと**外れた日だけ／1件納めた直後だけ**引き直せる（`DeliveryOrders.rollDaily`）
- ⚠ **知らせの重複抑止は `MessageLog` の側にある**（`info` の同じ文を続けて出さない）。
  **呼び出し側に印を持たせないこと。**⚠ **`sale` と `event` は抑止しない**（出来事は回数が情報）
- ⚠ **0件のとき「理由」を書き分ける。**「絞り込んだ結果」と「そもそも無い」は別物で、
  一緒にすると**序盤に何も知らないまま『揃っている』と言われる**（#48）

### 値と規則の構造（知らずに触ると符号が壊れる）

- **買値は全品同じ率**（`PURCHASE_RATE`）。これだけで
  `作る利益 − 転売利益 ＝ 加工利益 × 買値率` が成り立ち、
  **転売は薄利／作るほうが儲かる／深く作るほど取り分が増える**が同時に満たされる。
  ⚠ **tier ごとに率を分けないこと。**分けると符号が揃わなくなる
- **tier は「加工の深さ」であって「高級さ」ではない。**高級さは `贅沢さ` の軸
- **規則は適用範囲（`scope`）を宣言しない。**発火した効き目は**その品の tier で按分**され、
  一部が店全体へ、残りがその区画へ行く（tier1 は 90% が店全体／tier7 は 90% がその区画）。
  ⚠ **店全体ぶんは「置いてある区画数で割った平均」。**合計にすると効果の総量が区画数の
  **2乗**で伸びる（実測 13×10 で値段65倍）。**上限を足して抑えようとしないこと**
- ⚠ **取り合わせの規則は `SetRule` 1つに統一した**（#59 ／ 2026-09-14。`PairRule` ／
  `SignaturePairRule` ／ `SAME_ORIGIN_RULE` は無くなった）。**`SET_RULES` に1本足すだけで効く。**
  ⚠ **`members` は順序のある列で、効き目は先頭に当たった品にかかる。**
  **集合にすると R4「贅沢の隣に日用を置くと値が下がる」で日用品まで下がる。**
  ⚠ **`adjacent: false` が「離れていてよい」**（S1・S2）。**倍率は隣接より低くする**（PO 指定）——
  **位置を問わないボーナスを強くすると、置き方を考えなくてよくなる**
  ⚠ **`scope` を戻さないこと**（段3 で廃止。適用範囲は品の tier から按分）
- ⚠ **入荷解禁は `stockedBy` で絞って「どれか1本でも通るか」を見る**（#59）。
  **`UNLOCK_RULES` に1本足せば評価器を触らずに効く。**以前は `r.id === 'U1'` と ID で名指ししていて、
  **U3 を足しても無視された**
- ⚠ **規則が見る「産地」は、品に書いてある産地ではない**（#37 ／ 2026-09-14）。
  **条件言語の `産地` 述語と R5・D2 は `derive.ts` の `originReach()` を通る** ——
  **材料をすべて遡って行き着く島が1つに定まればその島、2島以上混ざれば `なし`。**
  ⚠ **書いてある産地をそのまま読むのは、商人が何を並べるか（U3・U4）と産地割引だけ。**
  **どちらも評価器の側に置いてある。**
  ⚠ **`産地` を見る規則を新しく書くと、自動的に「遡ったほう」を見る。**
  **実測**: 当たる品は **48 → 74 / 161品**（加工品106品のうち26品が1島に定まる）。
  ⚠ **「材料に1つでも入っていれば」にすると 154/161 になり、
  「並べ方で客足が動く幅は最大2倍」が常時かかる下駄に変わる**
- ⚠ **`stockedBy`（`rules.ts` の `StockedBy`）を評価器は読んでいない。**
  **並ぶ先ごとに関数を1本ずつ持っている**（`stockedByIslandMerchant` ／ `stockedByPeddler`）。
  ⚠ **規則データに `stockedBy` を足しても効かない。足すと規則が嘘になる**
- ⚠ **行商人の割増は `PeddlerStock` 側で掛ける。**
  **`purchasePrice()` に引数を足さないこと** —— `derive.ts` の「その島の中で率は2つだけ」が壊れる
- ⚠ **客に売れた経路以外の入金は `EconomyManager.addIncome()` を通す**（#28）。
  `addRevenue()` が積む `totalRevenue` は「**客に売れた額**」であって「入った金」ではない
- ⚠ **`materials.ts` の素材展開は `outputQuantity` で割る。**92本中64本が2個以上なので、
  割らないと要る素材を**段ごとに最大4倍**に見積もる（#33 で一度やって #23 で直した）

### 時間

- ⚠ **加工中は客が1人も来ない**（`skipMinutes` は `TIME_MINUTE_PASSED` を出さない）。
  **営業時間に食い込む加工は売上を失う**（実測 **2.6円/分**・線形）。
  ⚠ **無料枠は240分**（`fitsInToday` が24:00跨ぎを禁じ、**夜と朝がつながっていない**）
- ⚠ **航海日は無い。`atSea` は `src/` から消えた**（#74）。
  戻すなら `DAYS_AT_SEA = 1` と導出の復活だが、**周期が 10 → 11日になり
  `daysUntilReturn()` が 40 → 44日になる**ので #61 の対象が増える
- ⚠ **納品の個数は tier で割る**（#85。tier1:10 ／ tier7:1）。
  **一律だと tier7 は作るのに24日ぶんかかり、滞在10日に入らない**

## 進め方の決まり

- ⚠ **値を解かない。構造だけ決める**（PO 決定）。
  **後回しにできるのは値**（倍率・費用・確率・日数・上限）、
  **できないのは構造**（どの効き目を使うか／どこに差を置くか／何を上限にするか）。
  **仮置きの値はすべて #61 に集める。**→ 規則の全文は
  [issue-grouping.md §4](inception/plans/issue-grouping.md)
- **UI に触ったら、確認してほしいことを #47 の本文に1行足す。**
  テスト・型・ビルドが通っていても、画面の不具合はそこでしか出ない。
  ⚠ **確認は1件ずつ頼まない。**#47 にためて**最後にまとめて**見てもらう（PO 決定）
- ⚠ **先に言葉を置くと、判断がその言葉に寄る。**
  **消す／直す理由を書くときは、それが本当にその箇所に当たっているかを確かめる。**
  束M で誤った理由で文言を消し、**ペルソナ4人全員に指摘されて戻した。**
  **だから #79 には言い回しの案を書かない**（PO が指示する）
- **サブへ委任するときは、前提を1つ残らず依頼書に書く。**
  先例: [economy-rebalance-handoff-2.md](construction/plans/economy-rebalance-handoff-2.md)
- **確認用の道具**（`src/debug/`）: `M` 金+100万 ／ `N` 1日 ／ `B` 10日 ／
  `I` この島の品を各100 ／ `O` 全品を各100 ／ **`P` 行商人を呼ぶ** ／ `U` 強化を全系統1段。
  **出荷前に丸ごと外す**（#51）。外すのは `src/debug/` と `GameScene` の呼び出し1箇所、
  ⚠ **それと `GameScene.raiseStoryEvent()`**（確認用からしか呼んでいない）
