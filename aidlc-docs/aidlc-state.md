### いまの作りで、知らないと踏むこと

- **在庫は1つ。**`DisplaySlot` は数量を持たない。**店＝船倉**で倉と売り場は同じ場所なので、
  区画は「どの品を、どこに、どの向きで出しているか」だけを表す。
  **「補充」は「もっと手に入れる」の意味**で、棚をクリックすると仕入れ／クラフトへ飛ぶ
- **仕入れ・クラフト・改装は「行く場所」**（#58）。中央の領域がまるごと入れ替わり、棚は**消える**。
  ⚠ **覆うのではなく消す**（盤面は最大 x982 まで伸び、場所の領域 976 を6px はみ出す）。
  寸法は **`src/ui/layout.ts` だけ**が持つ。⚠ **写しを作らないこと**
- ⚠ **「棚に手が出せるか」の判定は `GameScene.isShelfBlocked()` の1つだけ。**
  以前は同じ `||` の連鎖が7箇所に散らばり、**1箇所だけ強化メニューが抜けていた**
- ⚠ **`<input>` を一覧と同じ入れ物に入れない。**打鍵のたびに作り直されてカーソルが飛ぶ。
  `SearchBox` と `CraftMenu` の回数入力はどちらも**開くとき1度だけ**置いている
- **買値は全品同じ率**（`PURCHASE_RATE`）。これだけで
  `作る利益 − 転売利益 ＝ 加工利益 × 買値率` が成り立ち、
  **転売は薄利／作るほうが儲かる／深く作るほど取り分が増える**が同時に満たされる。
  ⚠ **tier ごとに率を分けないこと。**分けると符号が揃わなくなる
- **tier は「加工の深さ」であって「高級さ」ではない。**高級さは `贅沢さ` の軸
- **規則は適用範囲（`scope`）を宣言しない。**発火した効き目は**その品の tier で按分**され、
  一部が店全体へ、残りがその区画へ行く（tier1 は 90% が店全体／tier7 は 90% がその区画）。
  ⚠ **店全体ぶんは「置いてある区画数で割った平均」。**合計にすると効果の総量が区画数の
  **2乗**で伸びる（実測 13×10 で値段65倍）。**上限を足して抑えようとしないこと**
- **未調整の値**: 強化費（総額 ¥2,236,000 ＝ 目標の22%）／**R5 の集客 1.6**。**段6で測り直す（#61）**
- ⚠ **`materials.ts` の素材展開は `outputQuantity` で割る。**85本中59本が2個以上なので、
  割らないと要る素材を**段ごとに最大4倍**に見積もる（#33 で一度やって #23 で直した）
- ⚠ **破棄ゾーン（外周56px）から盤面をくり抜いている**（#72）。
  上端 y0〜56 と盤面の1行目 y8〜66 が重なるので、くり抜かないと
  **一番上の行へ動かすと棚から外れる。判定と描画の両方でくり抜くこと**（`rects.ts`）
- ⚠ **0件のとき「理由」を書き分ける。**「絞り込んだ結果」と「そもそも無い」は別物で、
  一緒にすると**序盤に何も知らないまま『揃っている』と言われる**（#48 の教訓。
  `CraftMenu` は避けていたが `PurchaseMenu` に移っておらず、実機確認で出た）
- ⚠ **`<input>` は `src/ui/domInput.ts` を通す**（工房の回数／一覧の検索／仕入れの個数）。
  打鍵をゲームへ漏らさない・DOM が無くても落ちない・消すときキー入力を戻す・ESC の逃げ道 ——
  **1箇所でも忘れると操作が効かなくなる**
- ⚠ **段3 で1日の売上が 30% に落ちた**（13×10 で ¥248,743 → ¥74,889）。
  段3 前は `0.15 × 集客8.0 = 1.2` で**確率が1を超え、毎分かならず客が来ていた**。
  **目標1000万・200日はこの上で測り直す**

### 進め方の決まり

- **⚠ 値を解かない。構造だけ決める**（PO 決定 2026-09-12）。
  **後回しにできるのは値**（倍率・費用・確率・日数・上限）、
  **できないのは構造**（どの効き目を使うか／どこに差を置くか／何を上限にするか）。
  構造を後から変えると、その上で測った値が全部無効になる。
  **仮置きの値はすべて #61 に集める**（ラベル `数値調整`）。
  ⚠ **測り直すのは「今あるすべての issue を片付けたあと」**（PO 決定）。段5 の次ではない。
  **機能が1つ入るたびに数値の前提が変わる**ので、先に測ってもその測定は次の機能で無効になる。
  ⚠ **新しく仮置きの値を作ったら #61 の表に1行足す。**別 issue を立てない。
  例外は**符号が反転する変更**（例: 産地割引で「作る > 転売」が崩れないか）。これは構造の確認

- **UI に触ったら、確認してほしいことを #47 の本文に1行足す。**
  テスト・型・ビルドが通っていても、画面の不具合はそこでしか出ない。
  ⚠ **確認は1件ずつ頼まない。**#47 にためて**最後にまとめて**見てもらう（PO 決定）。
  `npm run dev -- --port 5173 --strictPort` は動き、**ユーザーは見られる**
- **サブへ委任するときは、前提を1つ残らず依頼書に書く。**
  先例: [economy-rebalance-handoff-2.md](construction/plans/economy-rebalance-handoff-2.md)
- **確認用の道具**（`src/debug/`）: `M` 金+100万 ／ `N` 1日 ／ `B` 10日 ／
  `I` この島の品を各100 ／ `O` 全品を各100 ／ `U` 強化を全系統1段。
  **出荷前に丸ごと外す**（#51）。外すのは `src/debug/` と `GameScene` の呼び出し1箇所
